本命盘一生不变，**运限**是把时间叠加到本命盘上得到的动态信息。
给一个目标日期，x-iztro 一次返回六个层级。

## 六个层级

| 层级 | 字段 | 周期 | 依据 |
| --- | --- | --- | --- |
| 大限 | `decadal` | 十年 | 五行局起运虚岁 + 阴阳男女的行进方向 |
| 小限 | `age` | 一年 | 生年地支 + 性别 |
| 流年 | `yearly` | 一年 | 目标日期所在的农历年 |
| 流月 | `monthly` | 一月 | 目标日期所在的农历月 |
| 流日 | `daily` | 一日 | 目标日期 |
| 流时 | `hourly` | 一时辰 | 目标时辰索引 |

大限与小限都是「按年龄推进」的，但规则完全不同，各走各的；
流年到流时则是「按日历推进」的。两套并行，共同构成一次查询的结果。

## 每个层级有什么

除小限与流年外，每个层级的结构相同：

| 字段 | 含义 |
| --- | --- |
| `index` | 该运限落在哪一个盘上位置（0–11，0 是寅宫） |
| `name` | 层级名，按输出语言翻译（「大限」「流年」……） |
| `heavenly_stem` / `earthly_branch` | 该运限的干支 |
| `palace_names` | 以该运限位置为命宫重排的十二宫名 |
| `mutagen` | 该运限干引发的四化星，顺序为禄、权、科、忌 |
| `stars` | 流耀在十二宫的分布，没有流耀的层级为空 |

<Callout title="palace_names 是重排后的宫名">
运限解读时要把运限所在的宫当作「这一步的命宫」，其余十一宫跟着重排。
`palace_names` 就是重排的结果，按盘上位置索引排列 ——
所以同一个格子在本命盘上是「财帛宫」，在某个大限里可能是「命宫」。
</Callout>

小限额外带虚岁：

```python
h.age.nominal_age     # 该日期对应的虚岁
```

流年额外带流年十二神：

```python
h.yearly.yearly_dec_star.suiqian12     # 按流年支重起的岁前十二神
h.yearly.yearly_dec_star.jiangqian12   # 按流年支重起的将前十二神
```

这两组与本命盘上宫位自带的 `suiqian12` / `jiangqian12` 是两回事：
本命的按出生年支起，流年的按目标年支起。

<Callout title="Rust 侧的 base 层">
Rust 里 `age` 与 `yearly` 的通用字段收在 `.base` 下
（`h.yearly.base.heavenly_stem`），因为它们各自还有专属字段。
序列化到 Python / Go 时这一层被展平，直接写 `h.yearly.heavenly_stem` 即可。
</Callout>

## 童限

大限从五行局决定的虚岁才开始（水二局 2 岁、火六局 6 岁）。
在此之前的年份不属于任何大限，这段时间用**童限**推算。

当目标日期落在起运之前，`decadal` 返回的就是童限，`name` 字段显示为「童限」。
字段结构不变，所以调用方不需要特殊处理，只在需要区分时看 `name`。

## 流耀

流年、流月等层级会带一批只在该层级存在的星，称为**流耀**
（流昌、流曲、流魁、流钺、流鸾、流喜、流禄、流羊、流陀、流马等）。
它们放在 `stars` 字段里，是一个「十二宫 × 该宫的流耀列表」的二维结构。

```python
for palace_index, stars in enumerate(h.yearly.stars or []):
    for s in stars:
        print(palace_index, s.name, s.scope)
```

星的 `scope` 字段标明它属于哪个层级：本命星是 `origin`，流年流耀是 `yearly`。

## 查询运限

```python
h = chart.horoscope("2024-10-1", 0)
```

```rust
let h = astrolabe.horoscope("2024-10-1", 0)?;
```

```go
h, err := astrolabe.Horoscope("2024-10-1", 0)
```

三种语言写法一致：运限从已排好的盘发起，出生参数、语言与配置都从盘上取，
只需给目标日期与时辰。返回的运限对象持有那张盘。

## 分界点会改变结果

运限的干支与虚岁受两个配置开关影响：

- `horoscope_divide` 决定运限年按正月初一还是立春换年，以及流月按初一还是节气分界
- `age_divide` 决定虚岁按农历年跨年加一，还是过了生日才加一

在年初或生日前后查询时，这两个开关会直接改变返回的干支与虚岁。
详见 [Config 详解](/zh/docs/guide/guides/config)。
