---
title: Semantic text (to_text)
description: Project a chart, a horoscope or a palace into Markdown text — for a language model, or for a person to read.
---

*For: everyone. This is the library's most direct use*

A chart has three projections in x-iztro: `to_json` / the DTO is the structured form for machines,
the translated fields are the display form for UIs, and **to_text is the natural-language form for
models and people** — a complete written description of the chart's facts. Feeding it to a language
model is its most common use, but it is not itself a prompt and contains no instructions. Assembling
that description by hand is tedious and easy to get incomplete, so every readable object carries its
own to_text.

The output is a **Markdown subset**: only `#`/`##`/`###` headings, `- label: value` lists,
`**bold**` and one narrow table. Rendered, it is a document; unrendered, the source reads just as
well, so pasting it into a chat box loses no structure.

| Entry | Contents |
| --- | --- |
| Chart `to_text` | The natal chart: basic info, a palace overview table, pattern hits, and the twelve palaces in detail starting from the Soul palace |
| Horoscope `to_text` | The horoscope: one section each for decadal, age fortune, yearly, monthly, daily and hourly, with each scope's mutagens, flowing stars and patterns |
| Palace `to_text` | A single palace, character-for-character identical to that palace's section in the natal text |
| Surrounded palaces `to_text` | The target palace, its opposite, and the wealth and career positions, one section each |
| `patterns_to_text` | The pattern-hit list on its own, from the natal or any horoscope perspective |

Everything generates in the **chart language**: a Chinese chart yields Chinese text, an English
chart English text. With a [knowledge pack](#text-with-readings), readings are inlined next to the
facts they belong to rather than appended (the mutagen notes are the one appendix).

## Usage

```python
chart = astro.by_solar("2000-8-16", 2, "female", language="en-US")
h = chart.horoscope("2025-1-1", 0)

text = f"{chart.to_text()}\n{h.to_text()}"   # str(chart) / str(h) are equivalent
```

```rust
let chart = by_solar("2000-8-16", 2, Gender::Female, true, Language::EnUS, Config::default())?;
let h = chart.horoscope("2025-1-1", 0)?;

let text = format!("{}\n{}", chart.to_text(), h.to_text());
```

```go
chart, _ := iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageEnUS, nil)
h, _ := chart.Horoscope("2025-1-1", 0)

natal, _ := chart.ToText()
fortune, _ := h.ToText()
```

The finer-grained entries:

```python
chart.palace("soul").to_text()                  # one palace
chart.surrounded_palaces("soul").to_text()      # surrounded palaces
chart.patterns_to_text()                        # natal patterns
h.patterns_to_text("yearly")                    # patterns from the yearly perspective
```

```go
chart.PalaceToText(iztro.PalaceTarget{Key: iztro.PalaceSoul})
chart.SurroundedPalacesToText(iztro.PalaceTarget{Key: iztro.PalaceSoul})
chart.PatternsToText(nil)
h.PatternsToText(iztro.ScopeYearly, nil)
```

On the Rust side these are `PalaceRef::to_text()`, `SurroundedPalaces::to_text()` and the free
functions of the `text` module (`astrolabe_to_text` / `horoscope_to_text` / `palace_to_text` /
`surrounded_palaces_to_text` / `patterns_to_text`); the convenience methods emit in the chart
language, the free functions take an explicit language — see
[Rust — TextOptions](/en/docs/rust/astro#textoptions). All three languages emit identical text.

## Structure at a glance

The skeleton of a natal text, top to bottom:

```text
# Natal Chart <solar date> <hour> <gender>
## Basic Info          four lines of merged fields + birth-year mutagens (with landing palaces)
## Palace Overview     a narrow table Palace | Major Stars | Minor Stars | Decadal, Soul palace first
## Patterns            the hit list; omitted entirely when there are no hits
## Palaces             from the Soul palace in order: soul, siblings, spouse, children, wealth, health, surface, friends, career, property, spirit, parents
### soul (ren woo) · Decadal 3-12   one section per palace: major, minor and adjective stars, trine & opposite, stem flying, twelve gods, age-fortune years
### siblings (xin si) · Decadal 13-22
…
```

A horoscope text:

```text
# Horoscope <solar date> (<lunar date>)
## Decadal Fortune · Soul Palace: Natal X (stem-branch)   mutagens, patterns + a twelve-palace table (Decadal | Natal | Major | Minor | Scope Stars); "Childhood Fortune" before the decadals start
## Age Fortune · Soul Palace: Natal X · Nominal Age N      palace names, mutagens, that palace's three star groups
## Yearly · Soul Palace: Natal X (stem-branch)             mutagens, patterns + a twelve-palace table (with a Twelve Gods column)
## Monthly · Soul Palace: Natal X (stem-branch)            palace names, mutagens, scope stars (with landing palaces), patterns
## Daily · …                                               as monthly
## Hourly · …                                              as monthly
```

Both the overview table and the detail sections start from the Soul palace and run by decreasing
palace index (soul, siblings, spouse, children, wealth, health, surface, friends, career, property,
spirit, parents) — not by cell position on the chart. The `Patterns` section lists every hit of the
[pattern engine](/en/docs/guide/concepts/patterns) on the natal chart, one per line: pattern name,
landing palace, forming stars; with no hits the section is omitted.

<Callout title="Lunar dates stay in Chinese">
`Lunar` is the one field that is not localized: the lunar date is written with Chinese numerals
whatever the chart language. `二〇二四年腊月初二` below is the 2nd day of the 12th lunar month,
2024. `Pillars` is the four pillars in iztro's romanization (午 renders as `woo` to keep it apart
from 戊 `wu`).
</Callout>

The decadal, yearly and finer scopes each carry a patterns line from their own perspective, with the
palace in parentheses written as re-laid out at that scope; age fortune has no pattern perspective.
Each scope's `Mutagen` line points to palaces of the **natal** chart (the mutagen stars sit on the
natal chart and are not re-laid out with the scope), so a landing palace is written `Natal friends`;
the scope-star lines and the twelve-palace tables are the ones that use the scope's re-laid-out
palace names. When the subject has not yet entered the decadals, the decadal section's heading and
table header read `Childhood Fortune` instead of `Decadal Fortune` — childhood and decadal are
different reading semantics.

## Format conventions

| Notation | Meaning |
| --- | --- |
| `# Natal Chart 2000-8-16 Tiger hour female`, `# Horoscope 2025-1-1 (…)` | Document title: the natal chart carries solar date, hour and gender; the horoscope carries the target date in solar and lunar form |
| `## Basic Info`, `## Palace Overview`, `## Patterns`, `## Palaces`, `## Mutagen Notes` | The natal sections; `## Decadal Fortune`, `## Age Fortune`, `## Yearly`, `## Monthly`, `## Daily`, `## Hourly` are the horoscope sections |
| `### soul (ren woo) · Decadal 3-12` | One section per palace: palace name, its stem and branch, and the nominal-age range when this palace is the decadal |
| `### career (bing xu) · Decadal 83-92 [Body Palace]` | The bracket marks this palace as also being the Body palace; `[Original Palace]` marks the [Original palace](/en/docs/guide/concepts/palaces#the-original-palace). The overview table's Palace column carries the same marks |
| `- label: value` | A fact line; several fields on one line are separated by ` · `, list items by `, ` |
| `\| Palace \| Major Stars \| Minor Stars \| Decadal \|` | The narrow overview table, Soul palace in bold; an empty cell is `—` |
| `emperor([+3])` | The parentheses hold [brightness](/en/docs/guide/concepts/stars#brightness) on a −3…+3 scale; a star without brightness has no parentheses |
| `sun([+3]) [A]` | The [mutagen](/en/docs/guide/concepts/mutagen), right after the star name (and brightness): `[A]`/`[B]`/`[C]`/`[D]` are Lu/Quan/Ke/Ji. A Chinese chart writes the full word, `化禄` |
| `moon [C]→friends` | The arrow points to the palace this mutagen star sits in on the **natal** chart. Birth-year mutagens and stem flying are written this way; no arrow when the star is not on the chart |
| `- Mutagen: moon [A]→Natal friends, …` | A horoscope scope's mutagen line: the landing palace is still the natal chart's, but inside a scope section a bare palace name means the scope's re-laid-out palace, so the `Natal` prefix marks the frame of reference |
| `attractive(M)→property` | Scope-star lines on the monthly and finer scopes: the arrow points to the palace the flowing star lands in, **as re-laid out at that scope** |
| `- Major Stars: Empty` | A palace with no major star says `Empty`; the minor and adjective lines are omitted when empty |
| `- Trine & Opposite: Opposite surface · Trine wealth, career` | This palace's opposite, and the other two palaces of its trine, always in wealth-position, career-position order ([surrounded palaces](/en/docs/guide/concepts/surrounded)) |
| `### Target Palace · soul (ren woo) · Decadal 3-12` | A palace heading in the surrounded-palaces text: the palace name is preceded by its role — `Target Palace`, `Opposite Palace`, `Wealth Palace`, `Career Palace` |
| `- Stem ren Flying: sage [A]→children, …` | The [flying-star mutagens](/en/docs/guide/concepts/mutagen#flying-stars) driven by this palace's stem: the mutagen stars and where each lands |
| `- Twelve Gods: Changsheng·weak, Boshi·dragon, Suiqian·downcast, Jiangqian·disastery` | One god from each of the four groups, written `group·god`, always in the order Changsheng-12, Boshi-12, Sui-qian-12, Jiang-qian-12; the yearly table's Twelve Gods column holds only the Sui-qian and Jiang-qian pair |
| `- Age Fortune Years: 5, 17, 29, …` | The [nominal ages](/en/docs/guide/concepts#four-concepts-to-get-straight-first) (虚岁) at which age fortune lands on this palace |
| `- **Empress and Minister Facing the Palace** (soul): empress([+3]), minister([+3])` | A pattern line: pattern name in bold, landing palace in parentheses, forming stars after the colon |
| `Scholar and Artist Flanking Life (soul, broken)` | `broken` appended in the parentheses: the pattern forms but is broken |
| `## Decadal Fortune · Soul Palace: Natal spouse (geng chen)` | Which natal palace this scope's Soul palace landed on; the parentheses hold that scope's stem and branch |
| `## Age Fortune · Soul Palace: Natal career · Nominal Age 25` | Where age fortune landed, and the nominal age |
| `\| Decadal Fortune \| Natal \| Major Stars \| Minor Stars \| Scope Stars \|` | A scope's twelve-palace table: the first column is **this scope's re-laid-out palace name**, the second the natal palace name; major and minor stars are the natal chart's, scope stars are this scope's |
| `- Palace Names: soul→Natal career, …` | Age fortune and the monthly and finer scopes have no palace table; this line carries the mapping instead: starting from that scope's soul palace, the left side is the scope's re-laid-out name and the right side is the natal one |
| `**emperor([+3])**: body` | A reading entry (only [with a knowledge pack](#text-with-readings)): the heading is the star, pattern or mutagen as written on its fact line, the body is the pack's text verbatim |
| `**emperor × empress (same palace)**: body` | A combined reading for two major stars sharing a palace |
| `Conditions: …` | The forming conditions, at the end of a pattern reading |

<Callout type="warn" title="The first column of a scope table is that scope's name — don't read it backwards">
`| spouse | wealth | …` says "within this decadal this cell is called the Spouse palace, and on the
natal chart it is the Wealth palace". A horoscope reading goes by the first column; the second is
there so you can map back to the natal chart. See
[Horoscopes](/en/docs/guide/concepts/horoscope#the-same-cell-a-different-palace-name).
</Callout>

<Callout type="warn" title="The (D) on artist and the (Y) on considery are part of the name">
In the en-US vocabulary the flowing stars carry their scope as a suffix inside the name: 运曲 is
literally `artist(D)`, 流禄 is `money(Y)`, 月鸾 is `attractive(M)`, and the daily and hourly
scopes use `(d)` and `(H)`. Likewise `considery(Y)` is the literal name of the star Nianjie
(年解), suffix included — iztro's vocabulary bakes it in to separate 年解 from 解神 (`considery`).
So `considery(Y)` appears among the natal **Adjective Stars**, where no scope is implied. Verify by
key, never by parsing the name.
</Callout>

Date fields echo the input verbatim, without zero padding: pass `"2000-8-16"` and you get
`Solar: 2000-8-16`.

## The five entries

| Entry | Output |
| --- | --- |
| Chart | The complete natal text above |
| Horoscope | The complete horoscope text above; natal information is not repeated, so the two concatenated make one full context |
| Palace | That palace's section from the natal detail (from its `### ` heading on), character-for-character — the natal text `contains` it |
| Surrounded palaces | A `## soul Trine & Opposite` heading plus one section each for the target, its opposite, and the wealth and career positions; each heading carries a role prefix (`### Target Palace · soul …`), and the fact lines are character-for-character the palace text |
| `patterns_to_text` | Pattern lines only, one per hit; from the natal perspective or any horoscope scope |

### Opposite Palace · surface (wu zi) · Decadal 63-72

- Adjective Stars: dignified
- Trine & Opposite: Opposite soul · Trine spirit, spouse

The palace text is one of those sections without the role prefix (from
`### soul (ren woo) · Decadal 3-12` on). The pattern text:

```text
# Patterns

- **Empress and Minister Facing the Palace** (soul): empress([+3]), minister([+3])
```

## Text with readings

The text above is facts only. Every to_text also has a form that takes a
[knowledge pack](/en/docs/guide/guides/knowledge-pack): readings are **inlined** next to the facts
they belong to — each palace's star readings right after that palace's fact lines, the pattern
readings right after the pattern list, and the mutagen notes at the end. The material is picked from
the pack according to the chart and quoted verbatim. The core only selects and assembles; it holds no
interpretive opinion of its own. Pass the bundled default pack and you get iztro-docs' readings; pass
a custom pack merged from overlays and you get yours. `by_solar` and the DTO output are unchanged.

```python
chart.to_text(knowledge=True)          # True takes the bundled pack for the chart language
chart.to_text(knowledge=my_pack)       # or any KnowledgePack
h.to_text(knowledge=True)
chart.palace("soul").to_text(knowledge=True)
chart.surrounded_palaces("soul").to_text(knowledge=True)
chart.patterns_to_text(knowledge=True)
h.patterns_to_text("yearly", knowledge=True)

chart.to_text(knowledge=True, config=PatternConfig(borrow=False))   # all four to_text take config
```

```rust
let pack = KnowledgePack::builtin(Language::ZhCN).unwrap();
let opts = TextOptions::new().knowledge(&pack);

chart.to_text_with(&opts);
h.to_text_with(&opts);
chart.palace(Palace::Soul).unwrap().to_text_with(&opts);
chart.surrounded_palaces(Palace::Soul).unwrap().to_text_with(&opts);
text::patterns_to_text_with(&hits, &names, &opts, chart.language);

let cfg = PatternConfig { borrow: false, ..PatternConfig::default() };
chart.to_text_with(&TextOptions::new().knowledge(&pack).pattern_config(&cfg));
```

```go
opts := iztro.TextOptions{Knowledge: iztro.BuiltinKnowledge()}   // or iztro.KnowledgeFrom(pack)

chart.ToTextWith(opts)
h.ToTextWith(opts)
chart.PalaceToTextWith(iztro.PalaceTarget{Key: iztro.PalaceSoul}, opts)
chart.SurroundedPalacesToTextWith(iztro.PalaceTarget{Key: iztro.PalaceSoul}, opts)
chart.PatternsToTextWith(opts)
h.PatternsToTextWith(iztro.ScopeYearly, opts)

cfg := iztro.PatternConfig{Borrow: iztro.Bool(false)}
chart.ToTextWith(iztro.TextOptions{Knowledge: iztro.BuiltinKnowledge(), PatternConfig: &cfg})
```

The pattern criteria (`config` / `pattern_config` / `PatternConfig`) are the same argument as
`patterns(config)` and act on both the text's pattern section and the pattern readings: change the
criteria and the hits and the readings that follow them change together. Omitted, the default
criteria apply.

### Where readings go, and deduplication

| Entry | Where the readings land |
| --- | --- |
| Chart | After the hit list under `## Patterns`: one entry per pattern; after each palace's `### ` fact lines: one entry per star in that palace; at the end, `## Mutagen Notes`: the four entries Lu, Quan, Ke, Ji |
| Horoscope | After the decadal and yearly twelve-palace tables, and after the fact lines of the monthly and finer scopes: one entry per scope star of that scope, one per pattern hit at that scope |
| Palace | After that palace's fact lines: one entry per star |
| Surrounded palaces | After each of the four palaces' fact lines |
| `patterns_to_text` | After the pattern list |

- A reading entry is written `**heading**: body`; the heading is the star exactly as written on its
  fact line (`**emperor([+3])**`, `**sun([+3]) [A]**`), the body is the pack's `intro` verbatim
  (Markdown, untrimmed), with a blank line between entries.
- A combined reading between major stars sharing a palace (the pack's `combinations`) is written
  `**emperor × empress (same palace)**: …` and comes first in that palace's readings; both
  directions are checked, so a reading recorded under only one of the two stars still appears,
  once per pair.
- Within a palace the stars are read in major, minor, adjective order; **the twelve gods get no
  readings**.
- A pattern reading is the `intro` body followed by a `Conditions: …` paragraph.
- The horoscope text reads only scope stars and each scope's patterns; natal stars are not repeated
  (those readings are in the natal text). A scope star or pattern that appears at several scopes is
  read only at the first scope it appears in.
- A star or pattern with no entry in the pack gets no entry and no placeholder.

Section and entry headings are translated into the chart language: on an English chart they read
`## Mutagen Notes` and `**emperor([+3])**`, while the bodies stay in the pack's language.

### Length

Readings come in full; trimming belongs to the application. Measured character counts for the same
chart (Chinese chart, default pack):

| Entry | Facts only | With readings |
| --- | --- | --- |
| Natal chart | 3,389 | 20,767 |
| Horoscope | 2,457 | 8,458 |
| Palace (Soul) | 222 | 1,141 |
| Surrounded palaces (Soul) | 924 | 6,312 |
| Patterns | 30 | 322 |

An English chart is longer (star names are words rather than two characters, and the structural
labels are longer): natal 6,757, horoscope 5,726, palace 464, surrounded palaces 1,911, patterns 83.
Any mainstream model's context window holds either comfortably; trimming is normally unnecessary.
The natal chart's readings dominate because every major, minor and adjective star on the chart has
an entry. For readings on a few palaces only, use the palace or surrounded-palaces entry; to lay
things out yourself, take the chart's sub-pack with
[`for_astrolabe`](/en/docs/guide/guides/knowledge-pack#picking-by-chart) and assemble from it.

### Custom packs

The pack is a parameter, so the result of merging overlays is passed the same way:

```python
pack = KnowledgePack.builtin().merged(KnowledgePack.from_json(open("my-school.json").read()))
chart.to_text(knowledge=pack)
```

The same chart with different packs yields byte-identical facts; only the reading entries change.

<Callout type="warn" title="English charts have no bundled pack">
The bundled default pack is zh-CN only. On an English chart (or any of the other four languages),
`knowledge=True` / `BuiltinKnowledge()` / `KnowledgePack::builtin(Language::EnUS)` raise
`invalid_argument` rather than silently falling back to no readings. Pass a pack explicitly — a
pack's language is not tied to the chart's, so an English chart with the Chinese pack gives English
headings and Chinese bodies.
</Callout>

## Six languages

The structural labels (`Basic Info`, `Major Stars`, `Trine & Opposite`, `Decadal`, …) exist in six
sets — zh-CN, zh-TW, en-US, ja-JP, ko-KR, vi-VN — and star names, palace names, stems and branches,
brightness, mutagens and pattern names are translated into the chart language. The same chart in
all six languages has a line-for-line matching skeleton; only the words differ. The lunar date is
written with Chinese numerals in every language (`二〇〇〇年七月十七`).

The mutagen mark follows the language: Chinese writes `化禄` and Japanese `化祿`, English `[A]`
(`[A]`/`[B]`/`[C]`/`[D]` are Lu, Quan, Ke, Ji), Korean `화록`, Vietnamese `hóa Lộc`. Word spacing
follows the language too: in Latin-script languages a space separates the star name from its
mutagen mark and the stem from the branch (English `sun [A]`, `### soul (ren woo)`; Vietnamese
`Thái Dương hóa Lộc`, `(Nhâm Ngọ)`), and compound labels likewise (`Natal spouse`); Chinese and
Japanese join them directly (`太阳化禄`, `(壬午)`, `本命夫妻`).

The Rust free functions take an explicit language: a Chinese chart rendered as en-US is
byte-identical to a natively English chart — star names are translated from their keys, not taken
from the names fixed on the chart, so nothing comes out mixed.

<Callout title="Chinese chart or English chart?">
Prefer a Chinese chart even when your product is in English. The English vocabulary is iztro's
interpretive word list — Ziwei is `emperor`, Qisha is `marshal` — brightness degrades to marks such
as `[+3]`, mutagens become `[A]`/`[B]`/`[C]`/`[D]`, the flowing stars carry scope suffixes inside
their names (`artist(D)`, `money(Y)`), and a couple of entries are not English words at all
(`considery`, `disastery`). None of that matches the rendering conventional in English-language Zi
Wei writing, so a model may not recognise it.

Mainstream models handle Chinese Zi Wei terminology well, and feeding them the Chinese text gets
better results. When you genuinely need English, attach a
[star-name table](/en/docs/guide/concepts/stars#star-name-table) alongside it.
</Callout>

## Wiring it to a model

The generated text is pure description and contains no instructions. In practice, put your analysis
request in front of it:

```python
system = ("You are a Zi Wei Dou Shu analyst. Answer from the given chart only; "
          "do not invent information that is not on it.")
user = f"""{chart.to_text()}

{chart.horoscope("2025-1-1", 0).to_text()}

Analyse this person's career prospects for 2025."""
```

To have the model interpret along one school's lines rather than freely, replace `chart.to_text()`
with `chart.to_text(knowledge=True)` (or pass your own pack) and the readings enter the context with
the chart. The text is Markdown, so a model reads the palace overview as a table and treats each
`### ` heading as a palace boundary — asking it to "quote the palace section" has a stable anchor.
For a fuller integration (tool calls, and not letting the model chart for itself) see
[Letting an AI read the chart](/en/docs/guide/guides/llm).

## When you need finer control

to_text covers the general case. To customise the text structure — describing only a few palaces, or
emitting JSON instead of text — walk the chart data and assemble it yourself; every field is public.
See the [Data model](/en/docs/guide/data-model).
