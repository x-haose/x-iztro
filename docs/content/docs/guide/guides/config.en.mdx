*For: developers · Zi Wei enthusiasts (the school differences in the first half need no code)*

Everything charting genuinely disagrees about is gathered into `Config`: a set of switches, plus override
tables that replace or extend the built-in data. The defaults match JS iztro exactly, so **passing no config
at all gives you the same chart iztro gives**.

| Switch | Accepts | Default | Governs |
| --- | --- | --- | --- |
| `year_divide` | `normal` / `exact` | `normal` | Which day the charting year's stem and branch turn over |
| `horoscope_divide` | `normal` / `exact` / `exactMonth` | `normal` | Which day horoscope stems/branches and the month pillar divide on (`exactMonth` is an x-iztro extension) |
| `age_divide` | `normal` / `birthday` | `normal` | When nominal age increments |
| `day_divide` | `forward` / `current` / `forwardCarry` | `forward` | Whether the late Zi hour counts as today or tomorrow |
| `algorithm` | `default` / `zhongzhou` | `default` | Algorithm school |
| `astro_type` | `heaven` / `earth` / `human` | `heaven` | Charting perspective (heaven / earth / human plate) |
| `void_placement` | `default` / `zhengPang` | `default` | Whether Jiekong and Xunkong take one palace or a main and a side palace (an x-iztro extension) |
| `leap_divide` | `default` / `nextMonth` | `default` | Which month a birth in a leap month is charted as (an x-iztro extension) |
| `tianma_placement` | `yearly` / `monthly` / `both` | `yearly` | Whether Tianma follows the birth year, the birth month, or both (an x-iztro extension) |
| `changsheng_direction` | `yinYang` / `gender` / `clockwise` | `yinYang` | Direction of the twelve Changsheng gods (an x-iztro extension) |
| `tianshang_tianshi` | `default` / `tianshiFriends` | `default` | Which of Tianshang and Tianshi sits in the Friends palace (an x-iztro extension) |
| `tianwu_placement` | `siShenYinHai` / `siShenHaiYin` | `siShenYinHai` | The four palaces Tianwu rotates through by month (an x-iztro extension) |
| `yearly12_placement` | `natalAndYearly` / `yearlyOnly` | `natalAndYearly` | Whether the natal chart carries the Sui-qian and Jiang-qian gods (an x-iztro extension) |
| `original_palace` | `primary` / `withSecondary` | `primary` | Whether xin and ren years also mark a secondary Original palace (an x-iztro extension) |
| `dou_jun_month` | `default` / `natal` | `default` | Whether the birth month behind Dou Jun follows the natal chart's late-Zi rule (an x-iztro extension) |
| `decadal_stem` | `palace` / `continuous` | `palace` | Whether a decade's stem is its palace stem or runs on from the Soul palace stem (an x-iztro extension) |
| `childhood_palace` | `sequence` / `spouse` | `sequence` | Whether the childhood period walks through palaces or stays in the Spouse palace (an x-iztro extension) |
| `age_mutagens` | `palaceStem` / `none` | `palaceStem` | Whether the minor limit (小限) has mutagens (an x-iztro extension) |
| `yearly_palace` | `taisui` / `age` | `taisui` | Whether the yearly Soul palace is the Taisui palace or the minor-limit palace (an x-iztro extension) |
| `scope_mutagen_stem` | `scope` / `scopeSoulPalace` | `scope` | Whether each horoscope layer's mutagens come from the layer's own stem or its Soul palace's stem (an x-iztro extension) |
| `monthly_palace` | `douJun` / `monthBranch` | `douJun` | Whether the first month sits at Dou Jun or in the Yin palace (an x-iztro extension) |
| `daily_palace` | `fromMonthly` / `afterMonthly` | `fromMonthly` | Whether the first day sits in the monthly Soul palace or the palace after it (an x-iztro extension) |
| `leap_daily` | `default` / `continuous` | `default` | Whether the days of the first half of a leap month keep counting on from the regular month (an x-iztro extension) |
| `hourly_palace` | `fromDaily` / `branch` | `fromDaily` | Whether the hourly palace counts from the daily Soul palace or follows the hour's branch (an x-iztro extension) |

iztro has none of the x-iztro extension switches; at their defaults they behave as iztro does, and the
`config` echoed on the astrolabe leaves those keys out (`horoscope_divide` is an iztro key and is always echoed).

There are three override tables besides: `mutagens` (a custom mutagen table), `extra_mutagens` (extra
mutagen stars) and `brightness` (a custom brightness table) — see
[Custom mutagen and brightness tables](#custom-mutagen-and-brightness-tables).

<Callout title="Nominal age">
**Nominal age** (虚岁) is East Asian age reckoning: you are 1 at birth and gain a year at the turn of
the year rather than on your birthday.
</Callout>

## How to pass it

```rust
use x_iztro::data::types::*;

let config = Config {
    algorithm: Algorithm::Zhongzhou,
    year_divide: YearDivide::Exact,
    ..Config::default()
};
by_solar("2000-8-16", 2, Gender::Female, true, Language::EnUS, config)?;
```

```python
from x_iztro import ChartConfig
from x_iztro.enums import Algorithm, YearDivide

config = ChartConfig(
    algorithm=Algorithm.ZHONGZHOU,
    year_divide=YearDivide.EXACT,
)
astro.by_solar("2000-8-16", 2, "female", language="en-US", config=config)
```

```go
cfg := &iztro.Config{
    Algorithm:  "zhongzhou",
    YearDivide: "exact",
}
iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageEnUS, cfg)
```

```js
import { astro, Algorithm, YearDivide } from 'x-iztro';

astro.bySolar('2000-8-16', 2, 'female', {
  language: 'en-US',
  config: { algorithm: Algorithm.ZHONGZHOU, yearDivide: YearDivide.EXACT },
});
```

Python, Go and JavaScript take only the keys you want to change and default the rest; Rust achieves the same
with `..Config::default()`. A misspelled key is never ignored: JavaScript and hand-written config JSON return
`invalid_argument` listing the valid keys, and Python's `ChartConfig` and Go's `Config` reject it at
construction or compile time.

## Year boundary: `year_divide`

Decides which day **the year stem and branch used for charting** turn over on.

| Value | Turnover point |
| --- | --- |
| `normal` (default) | The first day of the first lunar month (lunar New Year) |
| `exact` | The Beginning of Spring (立春, the solar term around 4 February) |

The year's stem and branch are the source of a whole chain: the natal mutagens, the soul and body
stars, the stems of the twelve palaces. So changing this switch can move a great deal of the chart.

**When you would notice**: for someone born between lunar New Year and the Beginning of Spring.
Those two dates are usually a few days to a couple of weeks apart, and a birthday inside that window
gets year stem-branch pairs one step apart under the two settings.

<Callout title="When to choose exact">
The Bazi (Four Pillars) system turns the year over at the Beginning of Spring without exception, so
choose `exact` when you need to line up with a Bazi chart. Standard Zi Wei practice turns the year
over at lunar New Year, and `normal` is also iztro's default. If in doubt, leave it alone — changing
it means no longer matching iztro's default output.
</Callout>

<Callout type="warn" title="The year branch is used in three separate ways">
x-iztro reproduces a detail internal to iztro: not everything that depends on the year branch goes
through the same switch. The split is a fixed three:

1. **Follows `year_divide`'s year stem and branch**: the birth-year mutagens, the soul and body
   stars, the stems of the twelve palaces, Lucun, Qingyang, Tuoluo, Tiankui, Tianyue, Tianma,
   Hongluan, Tianxi, the twelve Changsheng gods and the twelve Boshi gods.
2. **Follows `horoscope_divide`'s year stem and branch**: every other year-derived adjective star,
   plus the twelve Sui-qian gods and twelve Jiang-qian gods on the natal chart.
3. **Follows `horoscope_divide`'s month boundary**: the **month pillar** among the natal four
   pillars.

The two switches can be set independently, so "major stars on one year branch and some adjective
stars on another" is a state that really occurs. It looks asymmetric, but it is iztro's actual
behaviour and has to be kept verbatim to hold zero divergence.
</Callout>

## Horoscope boundary: `horoscope_divide`

Decides which day **horoscope stems and branches**, the **natal month pillar** and stem-branch month
numbering divide on.

| Value | Year boundary | Month boundary |
| --- | --- | --- |
| `normal` (default) | Lunar New Year | The first of the lunar month, month stem by the Five Tigers rule |
| `exact` | The Beginning of Spring | Solar terms |
| `exactMonth` | Lunar New Year | Solar terms |

**When you would notice**: when the query date lands early in the year (between lunar New Year and
the Beginning of Spring) or around any solar-term changeover, the yearly and monthly stem-branch
pairs shift by one step, which in turn changes the horoscope mutagens.

`exactMonth` is an x-iztro extension that separates the two things iztro ties together: the monthly
mutagens change stem at the solar term while the year still turns at lunar New Year. Ling Donglai's
example (*紫微斗数命理学*, pp. 160–161): 2015-4-5, Qingming, is the 17th of lunar month 2; the monthly
Soul palace stays in month 2 while the mutagens already use the geng stem (the geng chen month). Yiting's
charting software likewise has "change month at the solar term" ticked (*如何看大限流年*, p. 215). Under all
three values the monthly Soul palace follows the lunar month; only the stem follows the solar terms. For
example 2025-1-31 (the 3rd of lunar month 1 of yi si, before the Beginning of Spring): `normal` gives
yearly yi si and monthly wu yin; `exact` gives yearly jia chen and monthly ding chou; `exactMonth` gives
yearly yi si and monthly ding chou. The natal month pillar follows the month boundary, as under `exact`.

Under `exact` and `exactMonth` the monthly list (`monthly_list` and its text) has one row per lunar month,
with the stem, branch and mutagens of the segment's first day: when a solar term falls inside a lunar month,
the stem after it is not in that row, and only a horoscope taken by date shows it.

<Callout>
This switch also changes **the natal chart's month pillar**, not just horoscopes. Take 2000-8-5 in
the Yin hour: under `normal` the four pillars are `geng chen - jia shen - yi wei - wu yin`, and
under `exact` they are `geng chen - gui wei - yi wei - wu yin` — the month pillar moves from jia
shen (甲申) to gui wei (癸未).
</Callout>

## Nominal-age boundary: `age_divide`

Decides when **nominal age** increments, which directly moves which palace age fortune lands on.

| Value | Increment point |
| --- | --- |
| `normal` (default) | A year is added at the turn of the lunar year |
| `birthday` | A year is added only after the lunar birthday |

**When you would notice**: when the query date falls between lunar New Year and the person's lunar
birthday. In that stretch the two settings differ by one nominal year, which puts age fortune on
adjacent palaces.

## Late Zi hour attribution: `day_divide`

Decides which day the day pillar is taken from for someone born between 23:00 and 24:00 (hour index
`12`).

| Value | Behaviour |
| --- | --- |
| `forward` (default) | The late Zi hour belongs to the **following** day, and charting uses that day's day pillar; the birth month and year stem and branch stay with the current day |
| `current` | The late Zi hour belongs to the **current** day, charted as the early Zi hour of that day |
| `forwardCarry` | The **whole date** of a late Zi birth moves to the following day, charted as that day's early Zi hour: at a month's end it moves into the next month, on lunar New Year's Eve into the next year (an x-iztro extension) |

**When you would notice**: only on charts with hour index `12`; every other hour is unaffected.
`forward` and `forwardCarry` part ways for these late Zi births: at a month's end (moving into the next
month) and on New Year's Eve (moving into the next year); with `fix_leap` on, also from the 15th of a leap
month to its end — `forward` keeps iztro's natal late-Zi exception and stays in the leap month for its second
half, while `forwardCarry` moves to the next day and then counts the next month under the half-month rule.
For example 2020-6-11 (the 20th of leap month 4), a male late Zi birth: `forward` puts the Soul palace in Si
and Zuofu in Wei, `forwardCarry` the Soul palace in Wu and Zuofu in Shen.

`forwardCarry` follows Li Tiebi, *紫微斗数命运学*, pp. 105–106: the day turns at 23:00, month ends
carry into the next month and New Year's Eve into the next year. The lunar birthday, birth month, year
stem and branch and zodiac animal all come from the following day, and the chart's lunar date,
`raw_dates` and four pillars are written accordingly; `solar_date`, the hour index and the sign stay as
passed in. A horoscope's target hour is treated the same way. Take 2024-2-9 (New Year's Eve of a gui-mao
year) in the late Zi hour: `forward` gives the year pillar gui mao, `forwardCarry` gives jia chen and
the Dragon, and the chart is the one for 2024-2-10 in the early Zi hour. A late Zi birth on the 15th of a
leap month moves to the 16th, and with `fix_leap` on it is then charted as the next month.

<Callout type="warn" title="Under forward the lunar day advances too, but the display string does not">
`forward` pushes both the day pillar **and the lunar day used for placing Ziwei** to the following
day, while the lunar date string shown on the chart still reads the **day of birth**.

Take 2000-8-16 in the late Zi hour: the lunar date still displays `Lunar 2000-7-17` (the 17th day of
the 7th lunar month), yet the four pillars come out as
`geng chen - jia shen - ding wei - geng zi` — the day pillar ding wei (丁未) already belongs to
17 August. Do not try to reason backwards from the lunar display string to the day pillar.
</Callout>

<Callout>
Whichever value you pick, the hour index field keeps the original input `12`; being attributed to
the following day does not turn it into `0` — so callers can always recover the true hour of birth.
</Callout>

## Algorithm school: `algorithm`

| Value | Notes |
| --- | --- |
| `default` (default) | The mainstream star-placement rules, matching JS iztro's default |
| `zhongzhou` | The Zhongzhou school |

Zhongzhou differs from the default school in four places, and **the mutagen table is not one of
them**:

| Change | `default` | `zhongzhou` |
| --- | --- | --- |
| How the soul star is looked up | From the **Soul palace branch** | From the **birth-year branch** (so rearranging onto another Soul palace no longer moves it) |
| The twelve Sui-qian gods | Dahao `dahao` | Suipo `suipo` |
| Adjective stars | Jielu `jielu`, Kongwang `kongwang` | Jiekong `jiekong`, Jiesha `jieshaAdj`, Dahao `dahao`, Longde `longde` |
| Tianshang and Tianshi | Tianshang in Friends, Tianshi in Health | Swapped for the other gender polarity, the two stars trading positions |

The Jielu, Kongwang and Jiekong entries in the adjective-star row are what you get with `void_placement` at
its default; with the main/side split both schools place Jiekong and its side palace, see the next section.

<Callout type="warn" title="algorithm does not change the mutagen table">
Geng's Hua Ke is Taiyin under both schools. To adopt a different mutagen reading use the custom
mutagen table below; do not expect `algorithm` to do it.
</Callout>

```python
astro.by_solar("1990-11-5", 4, "male", language="en-US",
               config=ChartConfig(algorithm=Algorithm.ZHONGZHOU))
```

## Jiekong and Xunkong: `void_placement`

Jiekong (截空) spans two adjacent palaces set by the birth-year stem (jia/ji Shen–You, yi/geng
Wu–Wei, bing/xin Chen–Si, ding/ren Yin–Mao, wu/gui Zi–Chou); Xunkong (旬空) spans the two palaces
left void by the ten-day cycle the birth year falls in. For both, **a yang year takes the yang palace
as the main void (正空) and a yin year the yin palace**; the other palace is the side void (傍空)
(Wang Tingzhi, *安星法及推断实例*, pp. 56–57).

| Value | Jiekong | Xunkong |
| --- | --- | --- |
| `default` (default) | Default school: the two palaces get Jielu `jielu` (yang) and Kongwang `kongwang` (yin), with no main/side distinction; Zhongzhou: Jiekong `jiekong` in the main void only | Xunkong `xunkong` in the main void only |
| `zhengPang` | Both schools: Jiekong `jiekong` in the main void, side Jiekong `pangJiekong` in the side void; the default school no longer places Jielu and Kongwang | Xunkong `xunkong` in the main void, side Xunkong `pangXunkong` in the side void |

**When you would notice a difference**: on every chart. Under the default school Jiekong's two
palaces are the same two that hold Jielu and Kongwang, only named by main and side; Xunkong gains its
side palace. The default matches iztro, which has no `zhengPang`.

```python
from x_iztro.enums import VoidPlacement

astro.by_solar("2000-8-16", 2, "female",
               config=ChartConfig(void_placement=VoidPlacement.ZHENG_PANG))
```

```rust
by_solar("2000-8-16", 2, Gender::Female, true, Language::EnUS,
    Config::default().with_void_placement(VoidPlacement::ZhengPang))?;
```

<Callout type="warn" title="How pattern rules read the side voids">
The pattern engine's "Kongwang stars" set (the breaking condition of patterns such as Ri Yue Jia
Ming) counts both Jiekong palaces, side Jiekong and side Xunkong included; its "void stars" set (Lu
Shuai Ma Kun, the broad reading of Liang Chong Hua Gai) takes only the main voids of Jiekong and
Xunkong by default, and adds the side voids when `pang_kong` is on in the pattern settings
`PatternConfig`. Wang Tingzhi (*安星法及推断实例*, pp. 56–57) counts both palaces, the main void
weighing more; *紫微斗数精成* usually counts the main void only.
</Callout>

## Birth in a leap month: `leap_divide`

| Value | Which month a leap-month birth is charted as |
| --- | --- |
| `default` (default) | Per the charting argument `fix_leap`: on, the 1st–15th count as the current month and the 16th onwards as the next; off, the whole month counts as the current month |
| `nextMonth` | The whole month counts as the next month; `fix_leap` has no effect |

`nextMonth` follows *紫微斗数讲义* (Lu Binzhao's text), pp. 33–34, and *紫微斗数精成*, p. 11. The
Soul and Body palaces, Zuofu and Youbi, the month-based adjective stars, the month horse and the birth
month behind Dou Jun all move with it; leap months in the monthly horoscope always divide at the 15th
and are unaffected.

<Callout title="How it relates to fix_leap">
`fix_leap` is iztro's charting argument and can only pick between "divide at the 15th" and "whole month
as the current month". With `leap_divide` at its default, `fix_leap` decides; with `nextMonth`,
`leap_divide` decides, and `fix_leap` is still echoed on the astrolabe but takes no part. The month-split
switch of `monthly_list` (`monthFixLeap`) only governs how the monthly list is split and is independent of
both.
</Callout>

For example 2020-5-25 (the 3rd of leap month 4): by default it counts as month 4 with Zuofu in Wei;
under `nextMonth` it counts as month 5 with Zuofu in Shen.

## Tianma: `tianma_placement`

| Value | Tianma |
| --- | --- |
| `yearly` (default) | Year horse, by the birth-year branch: Yin/Wu/Xu → Shen, Shen/Zi/Chen → Yin, Si/You/Chou → Hai, Hai/Mao/Wei → Si |
| `monthly` | Month horse, by the birth month: months 1/5/9 → Shen, 2/6/10 → Si, 3/7/11 → Yin, 4/8/12 → Hai |
| `both` | Tianma takes the year horse, and the adjective star month Tianma `yuemaAdj` is placed at the month horse |

The month horse uses the same birth month as Zuofu and Youbi (already adjusted for leap months).
Sources: month horse only — Li Tiebi, *紫微斗数命运学*, p. 20; Xu Quanren, *紫微斗数命理学正解（一）*,
book pp. 39–40. Both horses — *紫微斗数一本通*, pp. 80, 84, 91; Cai Minghong, *秘仪*, p. 128. The books
call it 月马; iztro already uses 月马 for Tianma on the monthly horoscope layer, so the natal one is named
月天马 (en-US `month-horse`) to keep the names apart.

Under `monthly`, the Tianma that pattern rules see is the month-based one; under `both`, month Tianma is
an adjective star and takes no part in pattern rules.

## Changsheng direction: `changsheng_direction`

Changsheng always starts from the Five Elements class (water and earth Shen, wood Hai, metal Si, fire
Yin); only the direction differs:

| Value | Direction | Source |
| --- | --- | --- |
| `yinYang` (default) | Clockwise for yang men and yin women, counter-clockwise for yin men and yang women | Same as iztro |
| `gender` | Clockwise for men, counter-clockwise for women | *紫微斗数精成*, p. 22; Li Tiebi, *紫微斗数命运学*, p. 29 |
| `clockwise` | Always clockwise | *紫微斗数讲义*, p. 64 |

The direction of the twelve Boshi gods does not follow this switch.

## Tianshang and Tianshi: `tianshang_tianshi`

| Value | Placement |
| --- | --- |
| `default` (default) | Same as iztro: Tianshang in Friends, Tianshi in Health; with `algorithm = zhongzhou` the two swap for yin men and yang women |
| `tianshiFriends` | Tianshi in Friends, Tianshang in Health, whatever the gender and school (Li Tiebi, *紫微斗数命运学*, pp. 105, 135) |

## Tianwu: `tianwu_placement`

Tianwu rotates through four palaces by birth month:

| Value | Months 1/5/9 | 2/6/10 | 3/7/11 | 4/8/12 |
| --- | --- | --- | --- | --- |
| `siShenYinHai` (default) | Si | Shen | Yin | Hai |
| `siShenHaiYin` | Si | Shen | Hai | Yin |

`siShenHaiYin` is the placement in *紫微斗数精成*, pp. 20, 26.

## Sui-qian and Jiang-qian gods: `yearly12_placement`

| Value | Behaviour |
| --- | --- |
| `natalAndYearly` (default) | The natal chart places them by the birth-year branch, and the yearly horoscope again by the year's branch |
| `yearlyOnly` | Yearly stars only: the natal palaces carry none, the yearly horoscope's are unchanged |

`yearlyOnly` follows *紫微斗数一本通*, p. 44, and Li Tiebi, *紫微斗数命运学*, p. 115. Lin Gengfan,
*图解道教天文历算学·紫微斗数*, vol. 1, also places the two groups only as yearly stars but adds a natal
"Taisui" star (pp. 184, 195); that star is not supported yet. When the natal chart carries none, a palace's `suiqian12`,
`jiangqian12` and their keys are **empty strings**: the fields are still there with the same type, in the
same way major and minor stars carry an empty string when they have no brightness; in the Rust model
they are `None`. The text's twelve-gods line lists only the Changsheng and Boshi groups. Adjective stars
sharing a name (Xianchi, Huagai, Tiande, and Longde and Dahao under Zhongzhou) are separate stars and are
placed as usual.

## Original palace: `original_palace`

The Original palace is the palace whose stem equals the birth-year stem. The five-tiger rule gives the
Zi and Chou palaces the same stems as Yin and Mao, so xin years (Mao, Chou) and ren years (Yin, Zi) have
two qualifying palaces, and the other eight stems one each.

| Value | Behaviour |
| --- | --- |
| `primary` (default) | Same as iztro: only the qualifying palace among Yin to Hai is marked |
| `withSecondary` | The Chou palace in xin years and the Zi palace in ren years are also marked as the secondary Original palace |

Xu Quanren (*紫微斗数命理学正解（二）*, p. 12) takes Yin and Mao as primary and Zi and Chou as secondary.
The secondary palace is marked `is_secondary_original_palace` on the palace (`isSecondaryOriginalPalace`
in the DTO, present only when true) and labelled "Secondary Original Palace" in the text. Palace
addressing with `originalPalace` still points at the Yin/Mao palace; the secondary palace has no
addressing key of its own — it exists only in xin and ren years with the switch on, so a knowledge-pack
topic naming it could not select it on any other chart.

## Birth month behind Dou Jun: `dou_jun_month`

Dou Jun (where the monthly horoscope starts) counts the birth month backwards from the yearly palace and
then the birth hour forwards. iztro takes that birth month with the 16th onwards of a leap month as the
next month, late Zi hour included, while the natal chart keeps a late Zi birth in the leap month itself.
The two disagree on exactly one kind of chart: born on or after the 16th of a leap month, `fix_leap` on,
`day_divide = forward`, in the late Zi hour.

| Value | Birth month behind Dou Jun |
| --- | --- |
| `default` (default) | Same as iztro |
| `natal` | The natal chart's rule |

For example 2020-6-7 (the 16th of leap month 4) in the late Zi hour: the natal chart counts month 4;
Dou Jun counts month 5 under `default` and month 4 under `natal`, moving the monthly Soul palace one
palace on.

This is a consistency switch of the library itself, not any school's practice: the difference comes from
how iztro's natal chart and its Dou Jun take the birth month for a late Zi birth, and no source discusses
it. The school presets leave it alone.

## Horoscope conventions

The nine switches below change horoscopes only; the natal chart stays the same (`decadal_stem` also
changes the decadal stems on the palaces). Every layer's palace, palace names, mutagens and patterns follow
the chosen convention, and so do the text, [topic palace selection](/en/docs/guide/guides/to-text) and
[horoscope patterns](/en/docs/guide/concepts/patterns).

### Decadal stem: `decadal_stem`

| Value | Stem of a decade |
| --- | --- |
| `palace` (default) | The stem of its palace |
| `continuous` | The first decade takes the Soul palace stem; each later decade moves one stem on in stem order along the decades' direction: one stem forward when the decades run clockwise, one back when they run counter-clockwise |

`continuous` is the "decadal stem" rule of *紫微斗数精成*, p. 398: start from the natal Soul palace stem,
laid out forwards for yang men and yin women and backwards for yin men and yang women; the same page notes
that many schools keep the natal palace stems instead. The difference falls on the Zi, Chou, Yin and Mao
palaces. The book's example is Chiang Kai-shek's chart (a ding hai yin man, Soul palace jia chen, decades
running backwards): Mao gui and Yin ren match the palace stems, then Chou is xin (palace stem gui) and Zi is
geng (palace stem ren). The decadal branch does not change; decadal mutagens and decadal flow stars follow
the new stem.

### Childhood period: `childhood_palace`

| Value | Childhood period before the first decade |
| --- | --- |
| `sequence` (default) | From nominal age 1: Soul, Wealth, Health, Spouse, Spirit, Career in turn, each with its own palace stem |
| `spouse` | Always the Spouse palace: the childhood layer's palace names count from the Spouse palace as its Soul palace, and its mutagens use the Spouse palace stem |

`spouse` follows Yiting's course, lecture 02, pp. 14–17 (the Spouse palace is the parents' Children
palace; health questions read the childhood layer's Health palace). The Flying Star school's "read the
Spouse palace for the young" (Liang Ruoyu, *飞星斗数入门*, p. 44) agrees before the first decade. The
*梁若瑜飞星派紫微斗数课程*, PDF p. 19, goes further: "the Soul palace has no decade; everything before the second
decade (Parents or Siblings) should be analysed with the Spouse palace as the Taiji", so the first decade is read
through the Spouse palace too (in that page's example chart the first span, ages 3–12, is still printed on the
Soul palace). That is a different convention, not supported by this switch yet, which only changes the years
before the first decade.

### Minor-limit mutagens: `age_mutagens`

| Value | Minor limit (小限) |
| --- | --- |
| `palaceStem` (default) | Mutagens from the minor-limit palace stem |
| `none` | No mutagens: the layer's mutagen stars are empty, `mutagenStemKey` on the horoscope DTO's minor-limit layer is an empty string, and the text writes no mutagen line for it |

`none` is *紫微斗数精成*, p. 433: "the minor-limit palace stem does not fly mutagens". The minor-limit
layer has no flow stars either way.

### Yearly Soul palace: `yearly_palace`

| Value | Yearly Soul palace |
| --- | --- |
| `taisui` (default) | The Taisui palace, where the year's branch sits |
| `age` | The year's minor-limit palace |

`age` is how *天纪紫微斗数笔记* uses the minor limit as the year ("small yearly", p. 13), and its examples bear
it out: a woman born in the 41st year of the Republic (ren chen) with her Soul palace in Shen, whose
"both limits meet Health" at 56 (p. 59), has her minor limit in Mao, which is her Health palace. Only the
yearly Soul palace changes: the yearly palace names count from the minor-limit palace, and yearly patterns
and topics follow them; the yearly stem and branch, flow stars, Nianjie and the Sui-qian and Jiang-qian gods
still follow the year's branch, the yearly mutagens still use the year's stem (the minor-limit palace stem
when combined with `scope_mutagen_stem`), and Dou Jun still starts from the Taisui palace. The minor-limit
layer itself is unchanged.

### Stem of the horoscope mutagens: `scope_mutagen_stem`

| Value | Mutagens of the decadal, childhood, yearly, monthly, daily and hourly layers |
| --- | --- |
| `scope` (default) | The layer's own stem: the decadal stem, the childhood palace stem, the year, month, day and hour stems |
| `scopeSoulPalace` | The natal stem of the layer's Soul palace |

Sources for `scopeSoulPalace`: the Flying Star school takes the yearly mutagens from the yearly Soul palace
stem (Zhou Xingfei, *梁若瑜飞星派紫微斗数课程*, p. 21: in 2009, a ji chou year, the yearly Soul palace is
Chou, whose palace stem is xin, so the year flies with xin, not ji); the Heluo school keeps the natal stems
for every layer (Fangwairen, *河洛紫微斗数*, p. 28); Cai Minghong's first method uses the Taisui palace's natal
stem for the year (*华山钦天四化紫微斗数飞星秘仪*, book page 50, PDF p. 37). Heluo's "always the natal stems" means each layer's
palaces keep their natal stems and no layer stem is raised, which for each layer's mutagens comes to the
natal stem of its Soul palace — the same value as the Flying Star school.

Under the default config the decadal mutagens already come from the decadal palace stem, so on the decadal
layer this switch only shows a difference together with `decadal_stem = continuous`. The minor limit always
uses its palace stem.

The stem used is written on each horoscope layer: `mutagenStem` / `mutagenStemKey` on the DTO (Rust
`HoroscopeItem::mutagen_stem`, Python `mutagen_stem_key`, Go `MutagenStemKey`), present only when it differs
from the layer's stem; the text's mutagen line notes it ("Mutagen (Stem xin)"); topic selection reports
`scopeMutagenStemSource` as `scopeSoulPalace`, and each entry's `stemKey` is that layer's Soul palace stem.

### Monthly palace: `monthly_palace`

| Value | Monthly Soul palace |
| --- | --- |
| `douJun` (default) | Month 1 at Dou Jun: count the birth month backwards from the Taisui palace and the birth hour forwards, then one palace on per month |
| `monthBranch` | Month 1 is always the Yin palace; each month sits in the palace of its month branch (month 2 Mao, month 3 Chen …) |

`monthBranch` is the monthly layer of Cai Minghong's second method (*秘仪*, book pages 51–52, PDF pp. 37–38: when the year uses
the year stem's mutagens, the months skip Dou Jun and start month 1 at Yin with the Five Tigers rule; in a
yi chou year month 1 is wu yin and month 2 ji mao). Cai pairs his first method (the year on natal palace
stems) with Dou Jun and the second (the year on the year stem) with Yin, and says the two must not be mixed;
x-iztro does not enforce the pairing: the second method is the default `scope_mutagen_stem` plus
`monthBranch`, the first is `scopeSoulPalace` plus `douJun`. The first half of a leap month goes with that
month and the second half with the next, as with Dou Jun.

### Daily palace: `daily_palace`

| Value | Day 1 of the month |
| --- | --- |
| `fromMonthly` (default) | In the monthly Soul palace, then one palace on per day |
| `afterMonthly` | In the palace after the monthly Soul palace, then one palace on per day |

`afterMonthly` is from *梁若瑜飞星派紫微斗数课程*, p. 264: in the example chart (born in a wu wu year, lunar
month 10, Xu hour, Soul palace in Chou), the monthly palace of month 8 of 2010 is Xu (Children); the 4th
falls on Yin (Parents) and the 5th on Mao (Spirit), so day n is the n-th palace counted on from the monthly
palace.

### Days in a leap month: `leap_daily`

| Value | Daily palace in a leap month |
| --- | --- |
| `default` (default) | The first half of the leap month starts again from day 1 at the monthly Soul palace; from the 16th, the next month's monthly palace plus (day − 1) |
| `continuous` | The first half of the leap month keeps counting on from the days of the regular month of the same number; from the 16th, as the default |

`continuous` is Wang Tingzhi, *安星法及推断实例*, p. 85: when month 3 has a leap month, count the 30 days of
month 3 and then the first 15 days of the leap month, 45 days in all. When the regular month has 29 days,
the leap month's 1st is the 30th position. On how the second half of the leap month joins the next month the
text has only "month 4 also starts again from its 1st and counts 45 days", which yields no definite rule, so
from the 16th the default applies.

### Hourly palace: `hourly_palace`

| Value | Hourly Soul palace |
| --- | --- |
| `fromDaily` (default) | The Zi hour in the daily Soul palace, then one palace on per hour |
| `branch` | By the hour's branch: the Zi hour in the Zi palace, the Chou hour in the Chou palace, regardless of the day |

`branch` is the hourly layer of Xu Quanren, *学习紫微斗数的第一本书*, pp. 52–53, and of Wang Tingzhi's
teacher's line (*紫微斗数讲义*, p. 79).

### Not made into switches

Conventions the sources mention but give no definite rule for are not supported yet: starting the first
decade from the Parents or Siblings palace (Ling Donglai, *紫微斗数命理学*, p. 167, only reports that
*紫微斗数全书* does so, without saying when Parents and when Siblings, or what becomes of the Soul palace
decade); separate flow stars on the minor-limit layer (*紫微斗数精成*, p. 433, reads the minor limit against
the yearly flow stars only, and no other source gives a placement); yearly palace stems raised again from the
year stem with the Five Tigers rule (Cai Minghong's second method raises the Five Tigers only for the months,
and calls its yearly mutagens fixed images that do not transform further, with no yearly stem flying); the
Flying Star school's first decade read through the Spouse palace (stated on PDF p. 19 of the *课程*, a different
convention from Yiting's, which covers only the years before the first decade; not yet a value of
`childhood_palace`, see the childhood period above); how the days
of the second half of a leap month join the next month (see the leap-month days above).

## Charting perspective: `astro_type`

The Zhongzhou school reads one set of birth data as three charts, differing only in **which palace's
stem and branch the Five Elements class is taken from**:

| Perspective | Palace the class comes from | Soul palace of the new chart |
| --- | --- | --- |
| `heaven` (heaven plate) | Soul palace | Soul palace (i.e. the ordinary chart) |
| `earth` (earth plate) | Body palace | Body palace |
| `human` (human plate) | Spirit palace | Spirit palace |

Change the Five Elements class and the placement of Ziwei and Tianfu, the twelve palace names, the
Body palace branch, the twelve Changsheng gods, the decadals and the age fortune all move with it.
The minor stars, the adjective stars (Tianshang, Tianshi and Tiancai follow the Soul palace and are
re-placed), the twelve Boshi gods and the twelve Sui-qian and Jiang-qian gods carry over from the
heaven plate.

```python
earth = astro.by_solar("2000-8-16", 2, "female", language="en-US",
                       config=ChartConfig(astro_type=AstroType.EARTH))
```

```go
earth, _ := iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageEnUS,
    &iztro.Config{AstroType: iztro.AstroEarth})
```

```rust
let earth = by_solar("2000-8-16", 2, Gender::Female, true, Language::EnUS,
    Config::default().with_astro_type(AstroType::Earth))?;
```

<Callout>
JS iztro puts `astroType` on the options object of `withOptions`, because its `config()` is a global
singleton that cannot hold a value that varies per chart. x-iztro's configuration is passed per call
in the first place, so it goes straight into `Config` and works from both charting entry points.
</Callout>

### Rearranging onto an arbitrary stem and branch

Beyond the heaven, earth and human plates, you can rearrange onto any stem and branch as the Soul
palace:

```python
body = chart.palace(PalaceName.BODY)
earth = chart.rearranged(body.heavenly_stem_key, body.earthly_branch_key)
```

```go
earth, _ := chart.Rearranged(body.HeavenlyStemKey, body.EarthlyBranchKey)
```

```rust
let earth = chart.rearranged(body.heavenly_stem, body.earthly_branch)?;
```

Rearranging onto the Body palace's stem and branch gives the same result as
`astro_type = earth`.

## Custom mutagen and brightness tables

Mutagens and brightness are where school disagreement is most concentrated. `Config` lets you
**replace tables wholesale, by key**: supply the four mutagens for one heavenly stem and only that
stem changes, with every other stem still on the default table. Brightness works the same way.

### The mutagen table

One heavenly stem takes four stars, always in the order **Lu, Quan, Ke, Ji**, and all four must be
given.

```rust
let config = Config::default().with_mutagens(
    HeavenlyStem::Geng,
    [StarKey::TaiyangMaj, StarKey::WuquMaj, StarKey::TiantongMaj, StarKey::TianfuMaj],
);
by_solar("2000-8-16", 2, Gender::Female, true, Language::EnUS, config)?;
```

```python
cfg = ChartConfig(mutagens={
    "gengHeavenly": ["taiyangMaj", "wuquMaj", "tiantongMaj", "tianfuMaj"],
})
chart = astro.by_solar("2000-8-16", 2, "female", language="en-US", config=cfg)
```

```go
cfg := &iztro.Config{Mutagens: map[string][]string{
    "gengHeavenly": {"taiyangMaj", "wuquMaj", "tiantongMaj", "tianfuMaj"},
}}
```

With geng switched to "Tiantong takes Ke, Tianfu takes Ji", the mutagens on this geng-year chart
become:

```text
wealth warrior B
children sun A
career empress D
health fortunate C
```

A custom mutagen table also changes **every flying-star predicate** — which four stars a palace stem
flies out comes from the same table.

### Extra mutagen stars

Some schools have a stem transform more than four stars — geng, for one, with both Tiantong and
Tianxiang taking Hua Ji. The four-slot table holds one star per transformation, so the extra stars go
in `extra_mutagens` (wire key `extraMutagens`): stem key → mutagen key → list of star keys, added on
top of the four slots that stem uses (custom or default).

```rust
let config = Config::default()
    .with_extra_mutagens(HeavenlyStem::Geng, Mutagen::Ji, [StarKey::TianxiangMaj]);
```

```python
cfg = ChartConfig(extra_mutagens={"gengHeavenly": {"sihuaJi": ["tianxiangMaj"]}})
```

```go
cfg := &iztro.Config{ExtraMutagens: map[string]map[string][]string{
    "gengHeavenly": {"sihuaJi": {"tianxiangMaj"}},
}}
```

```js
astro.bySolar('2000-8-16', 2, 'female', {
  config: { extraMutagens: { gengHeavenly: { sihuaJi: ['tianxiangMaj'] } } },
});
```

Extra stars count exactly like the slot stars: in the stars' own mutagen marks, palace-stem flights,
every horoscope scope's mutagens, pattern rules and the text. The four slots themselves do not change —
`mutagenStarKeys` on palaces and scopes still has four items, and the extra stars are listed separately
in `extraMutagenStarKeys` (grouped by mutagen, like `{"sihuaJi": ["tianxiangMaj"]}`; the key is absent
when there are none).

| Method | When one transformation has more than one star |
| --- | --- |
| `flies_to` / `self_mutaged` | A transformation counts as flown in when any one of its stars sits in the target palace (or this palace) |
| `flies_one_of_to` / `self_mutaged_one_of` / `not_fly_to` / `not_self_mutaged` | Checked star by star, extra stars included like slot stars |
| `mutagen_stars` | For each transformation, the slot star first and then its extra stars |
| `mutaged_places` | Slots only, still four items in Lu, Quan, Ke, Ji order |

Within one stem a star may appear at most once across the slots and the extra stars: a star carries a
single mutagen mark, so one star taking both Ji and Ke cannot be marked, and charting fails with
`invalid_argument`.

### The brightness table

One star takes twelve brightness values, ordered by slot on the chart (slot 0 is the Yin palace),
and all twelve must be given; use an empty value (an empty string in Python, Go and JavaScript) where a slot has
no brightness. Major, minor and adjective stars all take one; the default table gives adjective stars
no brightness, so only the adjective stars listed here carry one.

Besides iztro's seven levels (`miao`, `wang`, `de`, `li`, `ping`, `bu`, `xian`) there is an eighth key,
`xian2` for 闲: in Wang Tingzhi's six levels (*安星法及推断实例*) and the seven levels of chapter 7 of
*紫微斗数一本通*, 闲 ranks below 平 and above 陷. The key is the pinyin with its tone number (xián),
kept apart from 陷 (xiàn), whose key is `xian`. The default table never uses it, and the pattern rules'
sun and moon brightness does not count it as dark.

A further key `di` stands for 地, copied as is from the brightness table of Wang Tingzhi's
*安星法及推断实例*, pp. 101–102 (Tanlang in Mao, Tianliang in You and the 禄 mutagen in Si are 地). The book's
glossary on p. 107 explains only 入庙, 坐旺, 落陷 and 平闲 and never defines 地, so x-iztro does not fold it
into 得 or any other level. The default table never uses it. The pattern rules only tell bright (庙, 旺)
from dark (陷, 不); 得, 利, 平, 闲 and 地 all sit between and count as neither.

```python
cfg = ChartConfig(brightness={
    "ziweiMaj": ["miao", "wang", "de", "li", "ping", "bu",
                 "xian", "miao", "wang", "de", "li", "ping"],
})
```

<Callout type="warn" title="Three hard rules">
1. **Keys only, never translated names**: `"ziweiMaj"` works, `"emperor"` and `"紫微"` do not.
2. **Lengths are validated strictly**: a mutagen entry must have 4 items and a brightness entry 12;
   one too many or too few is an error. Across the slots and the extra mutagen stars, a star may not
   appear twice within one stem.
3. **They are not echoed in the output**: the override tables are charting *input*, not part of the
   chart, so the `config` echoed on the astrolabe holds only the switches (the x-iztro extension switches
   are left out at their defaults too) and all three tables read back empty. If you need a record of them, keep your
   own copy of the config you passed.
</Callout>

## The config travels with the chart

The config used for charting is stored on the astrolabe and horoscopes read it from there, so
**a horoscope always uses the same config as the chart it came from** — you cannot end up with a
Zhongzhou natal chart and a default-school horoscope.

```python
chart = astro.by_solar("2000-8-16", 2, "female", language="en-US",
                       config=ChartConfig(age_divide="birthday"))
h = chart.horoscope("2024-10-1", 0)   # inherits age_divide=birthday
```

```go
chart, _ := iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageEnUS,
    &iztro.Config{AgeDivide: "birthday"})
h, _ := chart.Horoscope("2024-10-1", 0)   // as above
```

## Test coverage

The non-default values of the four boundary switches have 11,424 dedicated golden cases (covering
combinations at both the charting and horoscope layers), and the Zhongzhou chart types have another
12,488, spanning the Beginning-of-Spring window day by day, the late Zi hour, and the days around a
birthday — every boundary that produces a divergence. The custom mutagen and brightness tables have
a dedicated set of tests of their own. See [Accuracy](/en/docs/guide/about/accuracy).
