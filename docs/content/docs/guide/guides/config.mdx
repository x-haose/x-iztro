*适合：开发者 · 命理爱好者（前半页的流派差异不需要会写代码）*

排盘中真正有分歧的地方都收在 `Config` 里：一组开关，外加可替换或补充内置数据的覆盖表。
默认值与 JS iztro 完全一致，所以**不传配置就能得到与 iztro 相同的盘**。

| 开关 | 取值 | 默认 | 管什么 |
| --- | --- | --- | --- |
| `year_divide` | `normal` / `exact` | `normal` | 排盘年干支按哪天换年 |
| `horoscope_divide` | `normal` / `exact` | `normal` | 运限干支与月柱按哪天分界 |
| `age_divide` | `normal` / `birthday` | `normal` | 虚岁什么时候加一 |
| `day_divide` | `forward` / `current` / `forwardCarry` | `forward` | 晚子时算今天还是明天 |
| `algorithm` | `default` / `zhongzhou` | `default` | 算法派别 |
| `astro_type` | `heaven` / `earth` / `human` | `heaven` | 排盘视角（天盘/地盘/人盘） |
| `void_placement` | `default` / `zhengPang` | `default` | 截空、旬空安一宫还是分正傍两宫（x-iztro 扩展） |
| `leap_divide` | `default` / `nextMonth` | `default` | 闰月出生按哪个月安星（x-iztro 扩展） |
| `tianma_placement` | `yearly` / `monthly` / `both` | `yearly` | 天马按年支、按生月，还是两者都安（x-iztro 扩展） |
| `changsheng_direction` | `yinYang` / `gender` / `clockwise` | `yinYang` | 长生十二神顺逆（x-iztro 扩展） |
| `tianshang_tianshi` | `default` / `tianshiFriends` | `default` | 天伤、天使谁在仆役（x-iztro 扩展） |
| `tianwu_placement` | `siShenYinHai` / `siShenHaiYin` | `siShenYinHai` | 天巫按月轮转的四宫（x-iztro 扩展） |
| `yearly12_placement` | `natalAndYearly` / `yearlyOnly` | `natalAndYearly` | 本命盘安不安岁前、将前十二神（x-iztro 扩展） |
| `original_palace` | `primary` / `withSecondary` | `primary` | 辛壬年另标辅来因宫（x-iztro 扩展） |
| `dou_jun_month` | `default` / `natal` | `default` | 推斗君用的生月是否随本命盘的晚子时规则（x-iztro 扩展） |

x-iztro 扩展的开关 iztro 没有，取默认值时与 iztro 行为相同，星盘回显的 `config` 也不带这些键。

另有三张覆盖表：`mutagens`（自定义四化表）、`extra_mutagens`（附加四化星）与 `brightness`（自定义亮度表），
见[自定义四化表与亮度表](#自定义四化表与亮度表)。

## 怎么传

```rust
use x_iztro::data::types::*;

let config = Config {
    algorithm: Algorithm::Zhongzhou,
    year_divide: YearDivide::Exact,
    ..Config::default()
};
by_solar("2000-8-16", 2, Gender::Female, true, Language::ZhCN, config)?;
```

```python
from x_iztro import ChartConfig
from x_iztro.enums import Algorithm, YearDivide

config = ChartConfig(
    algorithm=Algorithm.ZHONGZHOU,
    year_divide=YearDivide.EXACT,
)
astro.by_solar("2000-8-16", 2, "female", config=config)
```

```go
cfg := &iztro.Config{
    Algorithm:  "zhongzhou",
    YearDivide: "exact",
}
iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageZhCN, cfg)
```

```js
import { astro, Algorithm, YearDivide } from 'x-iztro';

astro.bySolar('2000-8-16', 2, 'female', {
  config: { algorithm: Algorithm.ZHONGZHOU, yearDivide: YearDivide.EXACT },
});
```

Python、Go、JavaScript 都只需填要改的键，其余取默认；Rust 用 `..Config::default()` 达到同样效果。
写错的键名不会被忽略：JavaScript 与直接写 config JSON 时报 `invalid_argument` 并列出合法的键，
Python 的 `ChartConfig` 与 Go 的 `Config` 在构造或编译时就拒绝。

## 年分界点 `year_divide`

决定**排盘用的年干支**在哪一天换年。

| 取值 | 换年时点 |
| --- | --- |
| `normal`（默认） | 农历正月初一 |
| `exact` | 立春 |

年干支是一连串东西的源头：本命四化、命主与身主、十二宫宫干。
所以这个开关一旦改变，整张盘可能大幅不同。

**什么时候会看出差别**：出生在农历正月初一与立春之间的人。
这两个日期通常相差几天到半个月，落在这个窗口里的生日，两种配置排出的年干支相差一位。

<Callout title="什么时候该选 exact">
八字体系一律以立春换年，所以要与八字盘对齐时选 `exact`。
紫微斗数的通行做法是以正月初一换年，`normal` 也是 iztro 的默认。
拿不准就别动 —— 改了就不再与 iztro 的默认输出一致。
</Callout>

<Callout type="warn" title="年支分成三份用">
x-iztro 复刻了 iztro 内部的一处细节：依赖年支的东西并非全走同一个开关。
分工是固定的三条：

1. **跟 `year_divide` 的年干支**：生年四化、命主与身主、十二宫宫干、
   禄存、擎羊、陀罗、天魁、天钺、天马、红鸾、天喜、长生十二神、博士十二神
2. **跟 `horoscope_divide` 的年干支**：其余全部年系杂耀，
   以及本命盘上的岁前十二神与将前十二神
3. **跟 `horoscope_divide` 的月分界**：本命四柱里的**月柱**

两个开关可以分别设，所以「主星按一个年支、部分杂耀按另一个年支」是可能出现的。
这看起来不对称，但它就是 iztro 的实际行为，为保证零差异必须原样保留。
</Callout>

## 运限分界点 `horoscope_divide`

决定**运限干支**、**本命月柱**与**干支纪月**在哪一天分界。

| 取值 | 年分界 | 月分界 |
| --- | --- | --- |
| `normal`（默认） | 正月初一 | 初一，以五虎遁推月干 |
| `exact` | 立春 | 节气 |

**什么时候会看出差别**：查询日期落在年初（正月初一到立春之间）或每个节气交接的前后，
流年与流月的干支会差一位，进而改变运限四化。

<Callout>
这个开关还会改**本命盘的月柱**——不只是运限。
例如 2000-8-5 寅时：`normal` 下四柱是 `庚辰 甲申 乙未 戊寅`，
`exact` 下是 `庚辰 癸未 乙未 戊寅`，月柱由甲申变癸未。
</Callout>

## 虚岁分界点 `age_divide`

决定**虚岁**什么时候加一，直接影响小限落在哪个宫。

| 取值 | 加岁时点 |
| --- | --- |
| `normal`（默认） | 跨农历年即加一岁 |
| `birthday` | 过了农历生日才加一岁 |

**什么时候会看出差别**：查询日期落在农历新年与本人农历生日之间。
这段时间两种配置的虚岁相差一岁，小限也就落在相邻的两个宫。

## 晚子时归属 `day_divide`

决定 23:00–24:00 出生（时辰索引 `12`）的人，日柱按哪一天算。

| 取值 | 行为 |
| --- | --- |
| `forward`（默认） | 晚子时归**次日**，按次日的日柱排盘；生月与年干支仍按当天 |
| `current` | 晚子时归**当天**，按当日早子时排盘 |
| `forwardCarry` | 晚子时**整个日期**归次日，按次日早子时排盘：月底的晚子进下月，除夕的晚子进下一年（x-iztro 扩展） |

**什么时候会看出差别**：只影响时辰索引为 `12` 的盘，其余时辰完全无差异。
`forward` 与 `forwardCarry` 只在月底与除夕的晚子时（以及闰月十五的晚子时，见下）分歧。

`forwardCarry` 是李铁笔《紫微斗数命运学》p105–106 的口径：23 点换日，月底跨月、除夕跨年。
农历生日、生月、年干支与生肖都按次日，星盘上的农历日期、`raw_dates` 与四柱随之改写；
`solar_date`、时辰索引与星座仍按入参。运限的目标时辰同样按次日早子时算。
例如 2024-2-9（癸卯年除夕）晚子时：`forward` 下年柱癸卯，`forwardCarry` 下年柱甲辰、生肖龙，
星盘与 2024-2-10 早子时相同。闰月十五的晚子时进到十六，`fix_leap` 打开时随之按下月安星。

<Callout type="warn" title="forward 下农历日也一并进位，但展示串不变">
`forward` 会把日柱与**起紫微用的农历日**一起推到次日，
但星盘上的农历日期展示串仍显示**出生当日**。

例如 2000-8-16 晚子时：农历日期照旧显示「二〇〇〇年七月十七」，
四柱却是 `庚辰 甲申 丁未 庚子` —— 日柱丁未已是 8 月 17 日的。
读结果时别拿农历展示串去反推日柱。
</Callout>

<Callout>
无论选哪种，时辰索引字段都保留原始传入值 `12`，
不会因为归到次日就变成 `0` —— 这样调用方始终能知道出生的真实时辰。
</Callout>

## 算法派别 `algorithm`

| 取值 | 说明 |
| --- | --- |
| `default`（默认） | 通行的安星规则，与 JS iztro 默认一致 |
| `zhongzhou` | 中州派 |

中州派与默认派的差别集中在四处，**四化表不在其中**：

| 改动 | `default` | `zhongzhou` |
| --- | --- | --- |
| 命主怎么查 | 按**命宫地支** | 按**生年地支**（因此换命宫重排时命主不再变） |
| 岁前十二神 | 大耗 `dahao` | 岁破 `suipo` |
| 杂耀 | 截路 `jielu`、空亡 `kongwang` | 截空 `jiekong`、劫杀 `jieshaAdj`、大耗 `dahao`、龙德 `longde` |
| 天伤天使 | 天伤在仆役、天使在疾厄 | 阴阳男女互换，两星位置对调 |

杂耀一行的截路、空亡与截空是 `void_placement` 取默认值时的情形；分正傍时两派都安截空与傍截空，见下一节。

<Callout type="warn" title="algorithm 不改四化表">
庚干化科在两派下都是太阴 —— 要换四化取法请用下面的自定义四化表，
不要指望 `algorithm`。
</Callout>

```python
astro.by_solar("1990-11-5", 4, "male", config=ChartConfig(algorithm=Algorithm.ZHONGZHOU))
```

## 截空与旬空 `void_placement`

截空按生年天干占相邻两宫（甲己申酉、乙庚午未、丙辛辰巳、丁壬寅卯、戊癸子丑），
旬空占生年所在一旬空出的两宫。两者都是**阳年以阳宫为正空、阴年以阴宫为正空**，另一宫为傍空
（王亭之《安星法及推断实例》p56–57）。

| 取值 | 截空 | 旬空 |
| --- | --- | --- |
| `default`（默认） | 默认派：两宫分别安截路 `jielu`（阳宫）、空亡 `kongwang`（阴宫），不分正傍；中州派：只在正空安截空 `jiekong` | 只在正空安旬空 `xunkong` |
| `zhengPang` | 两派都在正空安截空 `jiekong`、傍空安傍截空 `pangJiekong`；默认派不再安截路、空亡 | 正空安旬空 `xunkong`，傍空安傍旬空 `pangXunkong` |

**什么时候会看出差别**：每张盘都会。默认派下截空的两宫与截路、空亡是同两宫，只是改用正傍命名；
旬空则多出傍空一宫。默认值与 iztro 一致，iztro 没有 `zhengPang`。

```python
from x_iztro.enums import VoidPlacement

astro.by_solar("2000-8-16", 2, "female",
               config=ChartConfig(void_placement=VoidPlacement.ZHENG_PANG))
```

```rust
by_solar("2000-8-16", 2, Gender::Female, true, Language::ZhCN,
    Config::default().with_void_placement(VoidPlacement::ZhengPang))?;
```

<Callout type="warn" title="格局判定怎么看傍空">
格局引擎的「空亡星」集合（日月夹命等格的破格条件）把截空两宫都算上，傍截空、傍旬空在其中；
「空曜」集合（禄衰马困、两重华盖的宽口径）默认只取截空、旬空的正空，格局口径 `PatternConfig` 的
`pang_kong` 打开时连傍空一并算。王亭之《安星法及推断实例》p56–57 正空、傍空两宫都算（正空重、傍空轻），
《紫微斗数精成》一般只论正空。
</Callout>

## 闰月出生 `leap_divide`

| 取值 | 闰月出生按哪个月安星 |
| --- | --- |
| `default`（默认） | 按排盘入参 `fix_leap`：打开时十五日及以前按本月、十六日起按下月；关闭时整月按本月 |
| `nextMonth` | 整月按下月，`fix_leap` 不起作用 |

`nextMonth` 是《紫微斗数讲义》p33–34（陆斌兆本文）与《紫微斗数精成》p11 的口径。
命宫、身宫、左辅右弼、月系杂耀、月马与斗君的生月都随之改变；流月的闰月一律十五日分界，不受影响。

<Callout title="与 fix_leap 的关系">
`fix_leap` 是 iztro 的排盘入参，只能在「十五日分界」与「整月本月」之间二选一。
`leap_divide` 取默认值时完全按 `fix_leap`；取 `nextMonth` 时由它决定，`fix_leap` 照样回显在星盘上但不参与计算。
`monthly_list` 的拆月开关（`monthFixLeap`）只管流月列表怎么拆，与两者都无关。
</Callout>

例如 2020-5-25（闰四月初三）：默认按四月，左辅在未；`nextMonth` 按五月，左辅在申。

## 天马 `tianma_placement`

| 取值 | 天马 |
| --- | --- |
| `yearly`（默认） | 年马：按生年地支，寅午戌申、申子辰寅、巳酉丑亥、亥卯未巳 |
| `monthly` | 月马：按生月，正五九申、二六十巳、三七十一寅、四八十二亥 |
| `both` | 天马安年马，另在月马之位安杂耀月天马 `yuemaAdj` |

月马的生月与左辅右弼所用的月相同（已按闰月口径修正）。出处：只用月马见李铁笔《紫微斗数命运学》p20、
许铨仁《紫微斗数命理学正解（一）》书 p39–40；年马、月马都安见《紫微斗数一本通》p80、p84、p91，
蔡明宏《秘仪》p128。书中称「月马」；iztro 已把流月层的天马叫「月马」，本命这一颗译作「月天马」以免同名。

`monthly` 下格局判定里的天马就是按月安的那一颗；`both` 下的月天马是杂耀，不参与格局判定。

## 长生十二神方向 `changsheng_direction`

长生都按五行局起（水土申、木亥、金巳、火寅），只是排列方向不同：

| 取值 | 方向 | 出处 |
| --- | --- | --- |
| `yinYang`（默认） | 阳男阴女顺行、阴男阳女逆行 | 与 iztro 一致 |
| `gender` | 男命顺行、女命逆行 | 《紫微斗数精成》p22；李铁笔《紫微斗数命运学》p29 |
| `clockwise` | 一律顺行 | 《紫微斗数讲义》p64 |

博士十二神的方向不随这个开关改变。

## 天伤、天使 `tianshang_tianshi`

| 取值 | 位置 |
| --- | --- |
| `default`（默认） | 与 iztro 一致：天伤在仆役、天使在疾厄；`algorithm = zhongzhou` 时阴男阳女两者对调 |
| `tianshiFriends` | 天使在仆役、天伤在疾厄，不分男女与派别（李铁笔《紫微斗数命运学》p105、p135） |

## 天巫 `tianwu_placement`

天巫按生月每四个月一轮：

| 取值 | 正五九 | 二六十 | 三七十一 | 四八十二 |
| --- | --- | --- | --- | --- |
| `siShenYinHai`（默认） | 巳 | 申 | 寅 | 亥 |
| `siShenHaiYin` | 巳 | 申 | 亥 | 寅 |

`siShenHaiYin` 是《紫微斗数精成》p20、p26 的安法。

## 岁前、将前十二神 `yearly12_placement`

| 取值 | 行为 |
| --- | --- |
| `natalAndYearly`（默认） | 本命盘按生年地支安，流年另按流年地支安 |
| `yearlyOnly` | 只作流年星：本命各宫不安，流年的岁前、将前照常 |

`yearlyOnly` 是《紫微斗数一本通》p44、李铁笔《紫微斗数命运学》p115 与林庚凡《图解道教天文历算学·紫微斗数》上册 p195 的做法。
本命不安时，宫位上的 `suiqian12`、`jiangqian12` 与它们的标识都是**空串**：字段照旧存在、类型不变，
写法与主星辅星无亮度时的空串相同；Rust 模型里是 `None`。文本的十二神行只写长生、博士两组。
同名的宫内杂耀（咸池、华盖、天德，中州派的龙德、大耗）是另一组星，照常安放。

## 来因宫 `original_palace`

来因宫是宫干等于生年天干的宫。五虎遁排到子丑两宫与寅卯两宫同干，所以辛年（卯、丑）、壬年（寅、子）
各有两宫合格，其余八干只有一宫。

| 取值 | 行为 |
| --- | --- |
| `primary`（默认） | 与 iztro 一致：只标寅至亥十宫里合格的那一宫 |
| `withSecondary` | 另把辛年丑宫、壬年子宫标为辅来因宫 |

许铨仁《紫微斗数命理学正解（二）》p12 以寅卯为主、子丑为辅。辅来因宫在宫位上记为
`is_secondary_original_palace`（DTO 的 `isSecondaryOriginalPalace`，只在为真时出现），文本里标「辅来因宫」。
宫位寻址的 `originalPalace` 仍然指寅卯那一宫；辅来因宫没有单独的寻址标识——它只在辛壬年、开了这个开关时存在，
知识包主题若写它，其余年份的盘就选不出这一宫。

## 斗君生月 `dou_jun_month`

斗君（流月起点）是流年宫逆数生月、再顺数生时。iztro 取这个生月时，闰月十六日起作下月，晚子时也不例外；
本命盘却规定晚子时不把闰月下半月作下月。两处口径在「闰月十六日以后、`fix_leap` 打开、`day_divide = forward`
的晚子时」这一种盘上不一致。

| 取值 | 斗君的生月 |
| --- | --- |
| `default`（默认） | 与 iztro 一致 |
| `natal` | 与本命盘同一规则 |

例如 2020-6-7（闰四月十六）晚子时：本命按四月；`default` 下斗君按五月，`natal` 下按四月，流月命宫顺移一宫。

## 排盘视角 `astro_type`

中州派把同一组出生数据看作三张盘，差别只在**用哪一宫的干支起五行局**：

| 视角 | 起五行局的宫 | 新盘的命宫 |
| --- | --- | --- |
| `heaven` 天盘 | 命宫 | 命宫（即常规排盘结果） |
| `earth` 地盘 | 身宫 | 身宫 |
| `human` 人盘 | 福德宫 | 福德宫 |

五行局一变，紫微天府的落点、十二宫名、身宫地支、长生十二神、大限小限全部跟着变；
辅星、杂耀（天伤天使天才随命宫走，会重新落位）、博士十二神、
岁前将前十二神沿用天盘。

```python
earth = astro.by_solar("2000-8-16", 2, "female",
                       config=ChartConfig(astro_type=AstroType.EARTH))
```

```go
earth, _ := iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageZhCN,
    &iztro.Config{AstroType: iztro.AstroEarth})
```

```rust
let earth = by_solar("2000-8-16", 2, Gender::Female, true, Language::ZhCN,
    Config::default().with_astro_type(AstroType::Earth))?;
```

<Callout>
JS iztro 把 `astroType` 放在 `withOptions` 的选项对象上，因为它的 `config()`
是全局单例、装不下按盘变化的值。x-iztro 的配置本来就随盘传入，
所以直接收进 `Config`，两个排盘入口都能用。
</Callout>

### 从任意干支起盘

天盘、地盘、人盘之外，也可以指定任意干支为命宫重排：

```python
body = chart.palace(PalaceName.BODY)
earth = chart.rearranged(body.heavenly_stem_key, body.earthly_branch_key)
```

```go
earth, _ := chart.Rearranged(body.HeavenlyStemKey, body.EarthlyBranchKey)
```

```rust
let earth = chart.rearranged(body.heavenly_stem, body.earthly_branch)?;
```

以身宫干支重排，结果与 `astro_type = earth` 一致。

## 自定义四化表与亮度表

四化与亮度是流派分歧最集中的两处。`Config` 允许**按标识整表替换**：
给出某个天干的四化就只改那个天干，未给出的天干仍用默认表；亮度同理。

### 四化表

一个天干配四颗星，顺序固定为**禄、权、科、忌**，必须给满四项。

```rust
let config = Config::default().with_mutagens(
    HeavenlyStem::Geng,
    [StarKey::TaiyangMaj, StarKey::WuquMaj, StarKey::TiantongMaj, StarKey::TianfuMaj],
);
by_solar("2000-8-16", 2, Gender::Female, true, Language::ZhCN, config)?;
```

```python
cfg = ChartConfig(mutagens={
    "gengHeavenly": ["taiyangMaj", "wuquMaj", "tiantongMaj", "tianfuMaj"],
})
chart = astro.by_solar("2000-8-16", 2, "female", config=cfg)
```

```go
cfg := &iztro.Config{Mutagens: map[string][]string{
    "gengHeavenly": {"taiyangMaj", "wuquMaj", "tiantongMaj", "tianfuMaj"},
}}
```

把庚干换成「天同化科、天府化忌」之后，这张庚年盘的四化变成：

```text
财帛 武曲 权
子女 太阳 禄
官禄 天府 忌
疾厄 天同 科
```

自定义四化表同时改变**全部飞星判断** —— 宫干化出哪四颗星走的是同一张表。

### 附加四化星

有的流派一干化出多于四颗星，例如庚干天同、天相同化忌。四槽表一类只放一颗星，
多出来的星写在 `extra_mutagens`（线协议 `extraMutagens`）里：天干标识 → 四化标识 → 星耀标识列表，
加在该天干生效的四槽（自定义的或默认的）之外。

```rust
let config = Config::default()
    .with_extra_mutagens(HeavenlyStem::Geng, Mutagen::Ji, [StarKey::TianxiangMaj]);
```

```python
cfg = ChartConfig(extra_mutagens={"gengHeavenly": {"sihuaJi": ["tianxiangMaj"]}})
```

```go
cfg := &iztro.Config{ExtraMutagens: map[string]map[string][]string{
    "gengHeavenly": {"sihuaJi": {"tianxiangMaj"}},
}}
```

```js
astro.bySolar('2000-8-16', 2, 'female', {
  config: { extraMutagens: { gengHeavenly: { sihuaJi: ['tianxiangMaj'] } } },
});
```

附加星与四槽之星同等对待：星耀的四化标记、宫干飞化、运限各层的四化、格局判定与文本都把它算进去。
四槽本身不变——宫位与运限的 `mutagenStarKeys` 仍是四项，附加星另列在 `extraMutagenStarKeys`
（`{"sihuaJi": ["tianxiangMaj"]}` 这样按四化分组，没有附加星时这个键不出现）。

| 方法 | 一类四化化出不止一颗星时 |
| --- | --- |
| `flies_to` / `self_mutaged` | 每一类四化里有任一颗星落在目标宫（或本宫）即算这一类飞入 |
| `flies_one_of_to` / `self_mutaged_one_of` / `not_fly_to` / `not_self_mutaged` | 逐颗星判断，附加星与四槽之星一样计入 |
| `mutagen_stars` | 每一类先四槽之星、后附加星 |
| `mutaged_places` | 只按四槽，仍是禄权科忌四项 |

同一天干里一颗星至多出现一次（四槽与附加星合计）：星耀只有一个四化标记，
一颗星既化忌又化科无从标记，排盘报 `invalid_argument`。

### 亮度表

一颗星配十二个亮度，按盘上位置排列（第一项是寅宫），必须给满十二项；
该位置无亮度时用空值（Python / Go / JavaScript 传空串）。主星、辅星、杂耀都可以给；
默认表不给杂耀亮度，只有列在这里的杂耀才带亮度。

亮度标识在 iztro 的七级（`miao` 庙、`wang` 旺、`de` 得、`li` 利、`ping` 平、`bu` 不、`xian` 陷）之外
另有一级 `xian2` 闲：王亭之《安星法及推断实例》的六级与《紫微斗数一本通》第七章的七级里，
闲都排在平之下、陷之上。标识取带声调数字的拼音（xián），与陷（xiàn）的 `xian` 区分。
默认表不出现闲；格局判定的日月明暗不把闲算作「暗」。

```python
cfg = ChartConfig(brightness={
    "ziweiMaj": ["miao", "wang", "de", "li", "ping", "bu",
                 "xian", "miao", "wang", "de", "li", "ping"],
})
```

<Callout type="warn" title="三条硬规则">
1. **只收标识，不收译名**：`"ziweiMaj"` 可以，`"紫微"` 不行。
2. **长度严格校验**：四化表必须 4 项、亮度表必须 12 项，多一项少一项都会报错；
   附加四化星与四槽合起来，同一天干里一颗星不能出现两次。
3. **不回显在输出里**：覆盖表是排盘的输入，不属于排盘结果，
   星盘上回显的 `config` 只有开关（x-iztro 扩展的开关取默认值时也不回显），三张表读回来是空的。
   自己要留档就自己存那份配置。
</Callout>

## 配置会跟着星盘走

排盘用的配置存在星盘上，运限从那里取，
所以**运限一定与排盘用同一套配置**，不会出现本命盘用中州派、运限用默认派的错配。

```python
chart = astro.by_solar("2000-8-16", 2, "female", config=ChartConfig(age_divide="birthday"))
h = chart.horoscope("2024-10-1", 0)   # 自动沿用 age_divide=birthday
```

```go
chart, _ := iztro.BySolar("2000-8-16", 2, iztro.GenderFemale, true, iztro.LanguageZhCN,
    &iztro.Config{AgeDivide: "birthday"})
h, _ := chart.Horoscope("2024-10-1", 0)   // 同上
```

## 测试覆盖

四个分界开关的非默认取值有 11,424 例专门的金标测试（含排盘层与运限层的组合），
中州派盘型另有 12,488 例，覆盖立春窗口逐日、晚子时、生日前后等所有会产生分歧的边界。
自定义四化表与亮度表另有一组专门的测试。见[准确性保证](/zh/docs/guide/about/accuracy)。
