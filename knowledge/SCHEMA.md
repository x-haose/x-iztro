# 知识包（Knowledge Pack）格式规范 v1

知识包是「语言无关标识 → 解读文本与门派属性」的 JSON 文件。

x-iztro 内核只负责**事实判定**（排盘、运限、格局、反推），而星耀怎么解读、格局意味着什么、宫位与四化的含义、星耀的门派属性（阴阳五行化气别号等）都属于
**门派观点**——不同典籍与流派本就互有分歧，没有唯一正确答案。知识包把这一层从内核里分出来：内核内嵌一份默认包保证
开箱即用；不认同其中任何一条的使用者，可以用覆盖包逐条改写，或整包替换成自己门派的内容。
排盘结果（星、格局、宫、四化）与知识包共用同一套语言无关标识，因此任何一个判定结果都能直接在包里查到对应条目。

本文是格式的权威规范。使用入门见文档站「使用指南 → 知识包」；三语言的加载/合并/查询 API 见文档站各语言的「知识包」页。

- **必须 / 不得**描述合法的包必须满足的约束；
- **实现行为**描述 x-iztro 内核对越界输入的实际处理，独立实现应保持一致。

## 1. 术语

| 术语   | 含义                                                 |
|--------|------------------------------------------------------|
| 包     | 一个符合本规范的 JSON 文档                           |
| 默认包 | 内核内嵌、随库分发的包（见 §8）                      |
| 覆盖包 | 以另一个包为底、只写想改动条目的包，经合并（§6）生效 |
| 条目   | 一个标识键对应的对象（一颗星、一条格局、一个宫位……） |
| 标识   | x-iztro 的语言无关 key，见 §3                        |

## 2. 文件格式与顶层字段

包是一个 UTF-8 编码的 JSON 对象。顶层字段：

| 字段       | 类型          | 必选     | 说明                                                                                        |
|------------|---------------|----------|---------------------------------------------------------------------------------------------|
| `schema`   | 整数          | **必须** | 格式版本，当前恒为 `1`。缺失或为 0 的包**必须**被拒绝                                       |
| `id`       | 字符串        | 必须     | 包标识，同一生态内应唯一（如 `iztro-docs`、`my-school`）                                    |
| `version`  | 字符串        | 必须     | 包版本，格式不限（默认包用 `日期+来源短commit`）                                            |
| `language` | 字符串        | 必须     | 文本语言，取 x-iztro 语言码之一：`zh-CN` `zh-TW` `en-US` `ja-JP` `ko-KR` `vi-VN`            |
| `extends`  | 字符串或 null | 可选     | 覆盖包声明其底包的 `id`。**纯声明性**：内核不依据它自动加载底包，加载与合并顺序由调用方决定 |
| `source`   | 对象          | 可选     | 来源与许可，见 §2.1                                                                         |
| `stars`    | 对象          | 可选     | 星耀条目，键为星耀标识，见 §4.1                                                             |
| `patterns` | 对象          | 可选     | 格局条目，键为格局标识，见 §4.2                                                             |
| `palaces`  | 对象          | 可选     | 宫位条目，键为宫位标识，见 §4.3                                                             |
| `mutagens` | 对象          | 可选     | 四化条目，键为四化标识，见 §4.3                                                             |
| `concepts` | 对象          | 可选     | 术语条目，键为 slug，见 §4.4                                                                |

**实现行为**：五个条目段与 `source` 写作 `null` 等同省略（照顾某些语言把空映射序列化为 null 的默认行为）；规范之外的顶层字段被
**静默丢弃**（不报错、不保留、合并后不存在），因此扩展数据不要放在自造字段里。

### 2.1 `source` 对象

全部字段皆为可选字符串：

| 字段           | 说明                                   |
|----------------|----------------------------------------|
| `name` / `url` | 来源名称与地址                         |
| `commit`       | 来源版本（如 git commit）              |
| `license`      | 来源许可证（如 `MIT`）                 |
| `author`       | 来源作者                               |
| `retrievedAt`  | 取得日期                               |
| `adapted`      | 文本非逐字转载时**必须**注明的改写说明 |

## 3. 标识（键）

所有条目键都是 x-iztro 的语言无关标识，与排盘输出中的 `*Key` 字段、各语言绑定的枚举/常量取值完全一致。权威值域来自内核，可通过
i18n 的
`allKeys` 查询（或查文档站「使用指南 → 语言无关标识」）。示例：

| 类别                 | 值域大小 | 例                                                  |
|----------------------|----------|-----------------------------------------------------|
| 星耀（`StarKey`）    | 162      | `ziweiMaj`、`wenchangMin`、`hongluan`、`changsheng` |
| 格局（`PatternKey`） | 64       | `zi_fu_tong_gong`、`huo_tan`                        |
| 宫位（`Palace`）     | 12       | `soulPalace`、`wealthPalace`                        |
| 四化（`Mutagen`）    | 4        | `sihuaLu`、`sihuaQuan`、`sihuaKe`、`sihuaJi`        |

**实现行为**：内核不校验条目键——未知键的条目被原样保留并参与合并，但任何按标识发起的查询都取不到它。写包时键拼写错误的症状是「条目静默失效」，
发布前应自查（把键集合与 `allKeys` 求差即可）。

## 4. 条目

所有条目字段都是可选的：省略（或写 null）表示「本包对此无话可说」。在覆盖包里，省略与写 null 都表示「不改动底包该字段」（见 §6）；
**不得**用空字符串表达缺省——空串会被视为有值并覆盖底包。

### 4.1 星耀条目（`stars.<starKey>`）

| 字段           | 类型   | 说明                                                                 |
|----------------|--------|----------------------------------------------------------------------|
| `name`         | 字符串 | 该语言的显示名（冗余存储，使包可脱离内核独立使用）                   |
| `category`     | 字符串 | `major`（主星）/ `minor`（辅星）/ `adjective`（杂耀）/ `dec`（神煞） |
| `group`        | 字符串 | 分组：杂耀的分类（如「交际类」）、神煞的组别（如「长生12神」）       |
| `attributes`   | 对象   | 门派属性，见 §4.1.1                                                  |
| `intro`        | 字符串 | 解读正文（§5）                                                       |
| `combinations` | 对象   | 主星的双星组合解读：键为**对方主星**的星耀标识，值为正文             |

### 4.1.1 `attributes` 对象

全部可选。多重五行说法（如贪狼「甲木，气为水」）拆为 `stem` + `fiveElements` +
`fiveElementsNote` 三个字段表达，第一说进前两者、其余进 note。

| 字段                           | 类型       | 取值                                                                      |
|--------------------------------|------------|---------------------------------------------------------------------------|
| `yinYang`                      | 字符串     | `yin` / `yang`                                                            |
| `fiveElements`                 | 字符串     | `wood` / `fire` / `earth` / `metal` / `water`                             |
| `stem`                         | 字符串     | 五行所带天干：`jia` `yi` `bing` `ding` `wu` `ji` `geng` `xin` `ren` `gui` |
| `fiveElementsNote`             | 字符串     | 五行补充说明（如「气为水」「己土(藏金、木)」）                            |
| `dipper`                       | 字符串     | 斗分（如「中天星系」「南斗第三星」）                                      |
| `chemistry`                    | 字符串     | 化气（如「尊贵」「善」）                                                  |
| `career`                       | 字符串     | 职业/主何事（如「官禄主」）                                               |
| `duty`                         | 字符串     | 职务                                                                      |
| `aliases`                      | 字符串数组 | 别号                                                                      |
| `elementColor` / `energyColor` | 字符串     | 五行色 / 能量色                                                           |

### 4.2 格局条目（`patterns.<patternKey>`）

| 字段         | 类型       | 说明                                                               |
|--------------|------------|--------------------------------------------------------------------|
| `name`       | 字符串     | 该语言的显示名                                                     |
| `quotes`     | 字符串数组 | 古籍引文，逐条独立                                                 |
| `conditions` | 字符串     | 成立条件的文字描述（注意：判定以内核格局引擎为准，此处是给人读的） |
| `intro`      | 字符串     | 解读正文                                                           |

### 4.3 宫位与四化条目（`palaces.<palaceKey>` / `mutagens.<mutagenKey>`）

| 字段    | 类型   | 说明           |
|---------|--------|----------------|
| `name`  | 字符串 | 该语言的显示名 |
| `intro` | 字符串 | 正文           |

### 4.4 术语条目（`concepts.<slug>`）

键为 slug：小写字母、数字与连字符（如 `san-fang-si-zheng`）。slug 不属于内核标识，由包自定义；默认包的 slug 清单见其内容本身。

| 字段    | 类型   | 说明 |
|---------|--------|------|
| `title` | 字符串 | 标题 |
| `intro` | 字符串 | 正文 |

## 5. 文本格式

正文类字段（`intro` / `conditions` / `combinations` 值）为 Markdown（纯文本亦可），约定：

- 允许的语法：段落（`\n\n` 分隔）、行内代码、加粗斜体、列表、引用块；**不得**使用 HTML 标签、图片、站外链接——包应自包含、可在任何环境渲染
- 行内代码惯例：星名与术语用反引号包裹（如 `` `帝王星` ``），渲染层可据此高亮
- 文本**不得**依赖页面上下文（「见上表」「点击此处」一类在包里没有意义）

## 6. 合并（覆盖包语义）

合并是二元运算 `merge(底包, 覆盖包) → 新包`，可链式叠加多个覆盖包（左结合）。 x-iztro 内核是合并的唯一实现（三语言绑定共用），规则如下。

### 6.1 条目段（stars / patterns / palaces / mutagens / concepts）

逐段、逐键处理覆盖包中出现的条目：

- 底包**无**该键 → 覆盖包条目整体加入（可以用覆盖包**新增**条目）；
- 底包**有**该键 → 逐字段合并，按字段类型：

| 字段类型                             | 合并语义                                    |
|--------------------------------------|---------------------------------------------|
| 标量（字符串）                       | 覆盖包非 null 则覆盖，null/省略则保留底包值 |
| 数组（`aliases`、`quotes`）          | **整体替换**（非 null 时），不做逐元素合并  |
| 映射（`attributes`、`combinations`） | 逐字段/逐键递归，缺省字段保留底包值         |

覆盖包中**未出现**的条目原样保留。由此推论：**合并无法删除**任何条目或字段；需要「减法」时用整包替换，不要用覆盖包。

### 6.2 元字段

| 字段                          | 合并语义                                                                                       |
|-------------------------------|------------------------------------------------------------------------------------------------|
| `id` / `version` / `language` | 覆盖包非空则覆盖                                                                               |
| `source`                      | 覆盖包的 source 只要有任一字段非空，即**整体替换**（不逐字段合并——来源信息混拼会产生错误署名） |
| `extends`                     | 保留底包的值（声明性字段，合并结果不改写）                                                     |
| `schema`                      | 保留底包的值；参与合并的每个包都必须先通过 §7 校验                                             |

## 7. 校验与版本兼容

实现在解析包时**必须**：

- 拒绝非法 JSON；
- 拒绝 `schema` 缺失、为 0、或大于实现所支持版本的包（错误信息应指明原因）。

版本策略：`schema` 只在**不向后兼容**的结构变更时递增（字段改名、语义改变、合并规则改变）。新增可选字段**不**递增版本——v1
的解析器遇到不认识的字段静默丢弃即可（§2 实现行为）。因此写包者不应依赖「未知字段能穿透实现」。

## 8. 默认包

内嵌默认包 `src/data/knowledge/iztro_docs.zh-CN.json`（仅 zh-CN）：

- 内容：107 颗星（主星 14 颗含双星组合解读、辅星 14、杂耀 34、神煞 45）、 64 条格局（引文/条件/解读）、12 宫、4 化、49 条术语；
- 底本为 [iztro-docs](https://github.com/SylarLong/iztro-docs)《学习》页的锁定 commit （`source.commit`），MIT 许可，作者
  Sylar Long；文本经 x-iztro 整理改写为第三人称释义口吻（`source.adapted` 注明；命理内容一仍其旧，只换表达）；
- 该 JSON 是**手工维护的源文件**：修改内容就是直接编辑它，格式、完整性与文本口吻由 `tests/knowledge_pack.rs`（含口吻红线断言）守护；
- 同步上游：对照 iztro-docs 新旧 commit 的页面差异，把变化条目改写后写回，更新 `source.commit`。

## 9. 覆盖包示例

一个完整可用的覆盖包：改紫微的解读与别号、给紫破组合换说法、改一条格局解读、新增一条术语。

```json
{
  "schema": 1,
  "id": "my-school",
  "version": "2026-08-19",
  "language": "zh-CN",
  "extends": "iztro-docs",
  "source": {
    "author": "某某门派",
    "license": "CC-BY-4.0"
  },
  "stars": {
    "ziweiMaj": {
      "intro": "本门认为紫微星……",
      "attributes": {
        "aliases": [
          "帝座"
        ]
      },
      "combinations": {
        "pojunMaj": "紫破同宫，本门断法是……"
      }
    }
  },
  "patterns": {
    "zi_fu_tong_gong": {
      "intro": "本门对紫府同宫的看法是……"
    }
  },
  "concepts": {
    "my-school-fei-xing": {
      "title": "本门飞星要诀",
      "intro": "……"
    }
  }
}
```

合并后：紫微的 `intro`、`aliases`、紫破组合换成本门版本，紫微的其余属性、其余 106 颗星、其余 63 条格局全部保留默认包内容；新增术语一条；
`id`/`version`/`source` 变为本包的（引用合并结果时署名随之改变，符合预期——内容已经是混合产物，由覆盖方对其负责）。

## 10. 许可与署名

- 基于他人内容制作的包**必须**在 `source` 保留原作者、许可证与出处；文本经过改写的**必须**填写 `source.adapted`；
- 默认包遵循上游 iztro-docs 的 MIT 许可；使用默认包内容时保留其 `source` 署名即可。
